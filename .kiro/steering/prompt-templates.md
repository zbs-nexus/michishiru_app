# プロンプトテンプレート — ミチシル チーム共通

AIにコードを書かせる際、以下のテンプレートを使って指示を出してください。

Kiro を使う場合、`.kiro/steering/` 配下の規約は自動で読み込まれるため「規約に従ってください」の一文は省略できます。他のAIツールを使う場合はテンプレートをそのまま使ってください。

---

## バックエンド（Lambda）用テンプレート

```
# 役割と目的

あなたは「ミチシル（ルート作成地図アプリ）」の開発を担当する上級エンジニアです。
プロジェクト内の以下フォルダに格納されている mdファイルの規則に厳格に従い、
高品質で保守性の高い Node.js コードを作成してください。

.kiro/steering

特に以下を必ず参照してください。
- naming-conventions.md（命名規則）
- naming-glossary.md（ドメイン用語辞書）
- back-lambda-rules.md（バックエンド規約）
- back-layer-architecture.md（レイヤー構成）
- back-data-access.md（データアクセス）

# 技術スタック

- 言語: Node.js (JavaScript / JSDoc を使用)
- プラットフォーム: AWS Lambda
- データベース: Amazon DynamoDB (AWS SDK v3 使用)
- テスト: Node.js 標準テストランナー

# 依頼内容

【実装したい機能・処理】
[ここに実装したい具体機能を記述。例: US-2 ルート作成処理のバックエンド]

【入力データ / 関連する型・データ構造】
[リクエストデータや既存のスキーマ・インターフェース情報を記述]

# 作成ルール

1. 依頼された機能の範囲内のみ変更・追加してください。不要なリファクタリングや
   関連のないファイルの修正は禁止します。
2. 用語辞書（naming-glossary.md）にない英単語を新しく使う場合は、
   使う前に辞書への追記案を提示してください。
3. spot（立ち寄り先）と waypoint（経路の座標点）を混同しないでください。
4. 実装上の判断理由、および規約に準拠したポイントについて
   簡潔に箇条書きで記載した説明書を作成してください。
```

## IaC（AWS CDK）用テンプレート

```
# 役割と目的

あなたは「ミチシル（ルート作成地図アプリ）」のインフラを担当する上級エンジニアです。
プロジェクト内の以下フォルダに格納されている mdファイルの規則に厳格に従い、
AWS CDK（TypeScript）のコードを作成してください。

.kiro/steering

特に以下を必ず参照してください。
- iac-rules.md（IaC・AWSリソース命名ルール）
- naming-conventions.md（命名規則）
- ミチシル_前提条件.md（システム構成）

# 技術スタック

- AWS CDK v2（TypeScript）
- テスト: Jest（aws-cdk-lib/assertions）
- デプロイ: GitHub Actions + OIDC

# 依頼内容

【追加・変更したいリソース】
[例: スポット検索用の DynamoDB テーブルを追加する]

# 作成ルール

1. 既存の Construct ID（論理ID）を変更しないでください。
   変更するとリソースが削除・再作成されます。
2. Lambda・S3・CloudFront には物理名を指定しないでください。
3. 環境（dev / prod）ごとに分かれることを前提に書いてください。
4. `iac/test/` にテストを追加し、`npm test` と `npx cdk synth` が通ることを確認してください。
5. APIキー・シークレットをコードに書かないでください。
```

---

## 注意事項

| 項目 | 内容 |
|---|---|
| パスは相対で書く | `.kiro/steering` のように書く。`C:\...` のような絶対パスはメンバーごとに違うため使わない |
| 規約の参照先を明示する | 「規約に従って」だけでは、どのファイルを読むべきか伝わらない |
| 用語の追加は必ず確認させる | 勝手に新しい英単語を使われると表記揺れの原因になる |
