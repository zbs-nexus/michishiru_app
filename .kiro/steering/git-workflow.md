# Git ワークフロー — ミチシル

---

## ブランチ戦略

| ブランチ | 役割 | 直接プッシュ |
|---|---|---|
| `main` | 最終統合先 | 禁止 |
| `feature/NZ-X` | レビュー対象（動作確認済みのみ） | 禁止（PRのみ） |
| `test/NZ-X` | 作業用 | 可 |

### フロー

```
test/NZ-X → feature/NZ-X → main
```

### ブランチ名の規則

| 種別 | 命名規則 | 例 |
|---|---|---|
| テスト用 | `test/NZ-<課題番号>` | `test/NZ-12` |
| フィーチャー | `feature/NZ-<課題番号>` | `feature/NZ-12` |
| バグ修正 | `fix/NZ-<課題番号>` | `fix/NZ-15` |
| 緊急修正 | `hotfix/NZ-<課題番号>` | `hotfix/NZ-20` |

**課題番号（`NZ-X`）の採番ルールは未決定。** `naming-conventions.md` の「未決定事項」を参照。

## コミットメッセージ規約

### フォーマット

```
<種別>(NZ-<課題番号>): <変更内容の要約>
```

### 種別一覧

| 種別 | 用途 |
|---|---|
| `feat` | 新機能 |
| `fix` | バグ修正 |
| `refactor` | リファクタリング |
| `docs` | ドキュメント |
| `style` | スタイル変更 |
| `test` | テスト |
| `chore` | 雑務 |

### ルール

| ルール | 詳細 |
|---|---|
| 1行目は50文字以内 | |
| 種別と課題番号を必ず含める | |
| 日本語OK | |
| 1コミット = 1つの変更 | |

## PR手順

### 前提条件

PR作成前に以下を実行し、すべて通っていることを確認する。

| 条件 | 確認方法 |
|---|---|
| 動作確認済み | ローカルで該当機能を操作して確認 |
| ESLint エラーなし | `frontend/` で `npm run lint` |
| ビルド通過 | `frontend/` で `npm run build` |
| バックエンドのテスト通過 | `backend/` で `npm test` |
| IaCのテスト通過（IaC変更時） | `iac/` で `npm test` |
| コンフリクトなし | |

補足: フロントエンドのテストはツール未決定のため、現時点では対象外。

### PR の方向

| フロー | 対象 |
|---|---|
| `test/NZ-X` → `feature/NZ-X` | 動作確認完了後 |
| `feature/NZ-X` → `main` | レビュー承認後 |

### レビュールール

| ルール | 詳細 |
|---|---|
| レビュアー最低1名 | |
| 承認後にマージ | |
| マージ後ブランチ削除 | |
| コンフリクトはPR作成者が解消 | |

### レビューで確認すること

| 観点 | 参照 |
|---|---|
| 命名が規則に沿っているか | `naming-conventions.md` |
| 用語辞書にない語を使っていないか | `naming-glossary.md` |
| レイヤーの責務を守っているか | `back-layer-architecture.md` |
| コンポーネントが肥大化していないか | `component-design.md` |

`naming-conventions.md` の「例外一覧」に載っているものは指摘不要。

### マージ方法

| ルール | 詳細 |
|---|---|
| `feature` → `main` | Squash merge |
| `test` → `feature` | 通常 merge |

## 規約ファイル自体を変更する場合

`.kiro/steering/` 配下のファイルを変更するときも、通常の開発と同じ手順を踏む。

| ルール | 詳細 |
|---|---|
| 直接 `main` にプッシュしない | PRを出す |
| コミット種別は `docs` を使う | 例: `docs(NZ-58): 用語辞書に spot を追加` |
| 用語辞書の変更はチーム全員に通知する | コード全体に影響するため |
| 各ファイル末尾の更新履歴に追記する | いつ何を変えたか追えるようにする |

## やってはいけないこと

| NG | 理由 |
|---|---|
| `main` に直接プッシュ | レビューなし |
| 動作確認せずに feature にマージ | レビュアーの負担 |
| 1 PR に複数課題 | revert しづらい |
| コンフリクト放置 | |
| マージ後ブランチ残す | |
| `--force` プッシュ | 他メンバーの作業消失 |
| `--no-verify` でフックを飛ばす | チェックが機能しなくなる |
