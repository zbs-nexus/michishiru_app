1. 概要

これまでルート作成APIへ送信する出発地点は、新宿駅周辺の固定座標を使用していました。 本変更では、ブラウザの Geolocation API を使用して実際のユーザー位置を取得し、 その座標を出発地点として使用するように改修しました。

変更前後の比較

項目 変更前 変更後
出発地点 固定座標（新宿駅周辺） ユーザーの現在地
位置情報の取得 なし Geolocation API
取得失敗時 — フォールバック（固定座標）を使用
対応環境 — PC / スマートフォン（HTTPS必須）

4. 実装詳細

4.1 useGeolocation.js（新規）

Geolocation API をラップした composable です。以下の機能を提供します。

戻り値 型 説明
currentLocation Ref<{lng, lat}> 取得した座標（またはフォールバック値）
isLocating Ref<boolean> 位置情報取得中かどうか
locationWarning Ref<string|null> 取得失敗時の警告メッセージ
isUsingFallback Ref<boolean> フォールバック値を使用しているか
fetchCurrentLocation () => Promise 現在地を取得する関数

設定値

設定 値 説明
タイムアウト 10秒 位置情報取得の最大待ち時間
キャッシュ有効期間 60秒 前回取得した位置情報の再利用期間
高精度モード 有効 GPS等を使用した高精度取得

4.2 エラーハンドリング

Geolocation API のエラーコードに応じて、ユーザー向けメッセージを生成します。

エラーコード 状況 表示メッセージ
PERMISSION_DENIED ユーザーが許可を拒否 位置情報の取得が許可されていません
POSITION_UNAVAILABLE 位置情報が利用不可 位置情報を取得できませんでした
TIMEOUT 取得がタイムアウト 位置情報の取得がタイムアウトしました
💡 フォールバック動作

位置情報の取得に失敗しても、ルート作成は中断されません。 フォールバック値（新宿駅周辺: 経度 139.702973, 緯度 35.686338）を使用して処理を続行します。

5. タイムアウトへの影響

5.1 各処理のタイムアウト設定

処理 タイムアウト 備考
位置情報取得 10秒 フロントエンド（Geolocation API）
createRoute Lambda 29秒 API Gateway の上限に合わせている
fetch（フロント） 設定なし ブラウザのデフォルト

5.2 ユーザー待ち時間の変化

ケース 位置情報 API 合計
最良ケース 1-3秒 5秒 6-8秒
通常ケース 1-3秒 15秒 16-18秒
位置情報タイムアウト 10秒 15秒 25秒
最悪ケース 10秒 29秒 39秒
⚠️ 注意

位置情報取得のタイムアウト（最大10秒）が追加されるため、 ユーザーの待ち時間が従来より長くなる可能性があります。 ただし、位置情報が拒否された場合は即座にフォールバックに切り替わるため、 追加の待ち時間は発生しません。

6. 動作環境

6.1 必須条件

条件 詳細
HTTPS Geolocation API は HTTPS 環境でのみ動作（localhost は例外）
ブラウザ対応 主要ブラウザはすべて対応（Chrome, Firefox, Safari, Edge）
ユーザー許可 初回アクセス時に位置情報の許可ダイアログが表示される

6.2 デバイス別の特性

デバイス 精度 取得速度 備考
スマートフォン（GPS有効） 高 速い（1-3秒） 最も正確
スマートフォン（GPS無効） 中 普通 Wi-Fi/基地局から推定
PC（Wi-Fi） 低〜中 遅い場合あり IPアドレスやWi-Fi APから推定
PC（有線LAN） 低 遅い場合あり IPアドレスから大まかに推定

7. コード例

useGeolocation の使用例

import { useGeolocation } from '@/composables/useGeolocation';

const {
  currentLocation,
  isLocating,
  locationWarning,
  isUsingFallback,
  fetchCurrentLocation
} = useGeolocation();

// 現在地を取得
const location = await fetchCurrentLocation();

// 取得結果を確認
console.log(location);  // { lng: 139.xxx, lat: 35.xxx }

// フォールバックを使用したかどうか
if (isUsingFallback.value) {
  console.log('位置情報が取得できなかったため、既定の場所を使用します');
  console.log(locationWarning.value);  // エラーメッセージ
}

8. 今後の改善案

案 内容 効果
事前取得 ホーム画面表示時に位置情報を取得してキャッシュ ルート作成時の待ち時間を削減
タイムアウト短縮 10秒 → 5秒に変更 最悪ケースの待ち時間を削減
位置情報の表示 取得した現在地をホーム画面に表示 ユーザーが出発地を確認できる
手動入力 ユーザーが出発地を地図上で選択可能に 任意の場所からルート作成が可能

9. リアルタイム現在地表示（案内画面）

ルート案内画面では、ユーザーの現在地をリアルタイムで追跡し、 Google Maps風のマーカーで表示します。

9.1 追加ファイル

ファイル 状態 内容
useLocationTracking.js 新規 リアルタイム位置追跡用の composable
RouteMap.vue 変更 現在地マーカーの表示機能を追加
RouteNavigationMap.vue 変更 位置追跡を統合
global.css 変更 現在地マーカーのスタイルを追加
mapDefaults.js 変更 現在地マーカー関連の定数を追加

9.2 マーカーのデザイン

Google Maps風の現在地マーカー

  • 青い円（中心）: 現在位置
  • 半透明の円（外側）: 精度範囲
  • 三角の矢印: 向いている方向

9.3 useLocationTracking の仕様

戻り値 型 説明
currentLocation Ref<{lng, lat}> 現在地の座標
heading Ref<number|null> 方向（度、北を0度として時計回り）
accuracy Ref<number|null> 精度（メートル）
isTracking Ref<boolean> 追跡中かどうか
trackingError Ref<string|null> エラーメッセージ
startTracking () => Promise 追跡を開始
stopTracking () => void 追跡を停止

9.4 設定値

設定 値 説明
更新間隔 5秒 位置情報の取得間隔
タイムアウト 10秒 1回の取得の最大待ち時間
キャッシュ 0秒 常に最新の位置を取得
高精度モード 有効 GPS等を使用

9.5 方向の計算

方向（heading）は以下の優先順位で決定されます：

  1. Geolocation API の heading: デバイスが移動中の場合に取得できる
  2. 前回位置からの計算: 約10m以上移動した場合、2点間の方位角を計算
  3. null: 上記いずれも取得できない場合（矢印は非表示）
💡 バッテリー消費について

watchPosition ではなく setInterval + getCurrentPosition を 使用しているため、更新間隔を明示的に制御でき、バッテリー消費を抑えやすくなっています。 必要に応じて更新間隔を10秒に変更することも可能です。

10. テスト観点

9.1 正常系

  • 位置情報を許可した場合、実際の座標でルートが作成されること
  • スマートフォンで GPS 有効時に正確な位置が取得されること
  • PC で Wi-Fi 環境下で位置が取得されること

9.2 異常系

  • 位置情報を拒否した場合、フォールバック座標でルートが作成されること
  • タイムアウトした場合、フォールバック座標でルートが作成されること
  • 非対応ブラウザでフォールバック座標が使用されること
  • HTTP 環境で Geolocation API がエラーになり、フォールバックが使用されること

9.3 境界値

  • タイムアウト直前（9.9秒）で位置情報が取得された場合
  • キャッシュ有効期間内（60秒以内）に再度取得した場合
🔒 セキュリティ注意

位置情報はユーザーのプライバシーに関わる機密データです。 取得した座標はルート作成 API への送信にのみ使用し、 ログへの出力やローカルストレージへの保存は行わないでください。
