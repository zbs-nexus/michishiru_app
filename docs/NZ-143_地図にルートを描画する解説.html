地図にルートを描画する 〜 NZ-143 でやったこと

はじめての人でも読める版 ／ 対象ブランチ feature/NZ-143 ／ 最終更新 2026-09-09

1. そもそも何をしたかったのか

ミチシルは「散歩の条件を入れると、AI がおすすめコースを作ってくれる」アプリです。 その最後の工程が Step 6「地図にルートを表示する」で、ここが今回の担当範囲です。

やりたかったこと
  • 地図を表示する
  • その上にルートを示す線を引く
  • 立ち寄るスポットに番号付きの印を置く
  • ルート全体がちょうど収まる位置まで地図を寄せる

このうち「地図」「スポットの印」「地図の寄せ」はできていたのに、 線だけがどうしても出ないという状態が続きました。そこを解決したのが今回です。

2. 先に言葉の説明

この先で出てくる用語を、ここでまとめて説明します。分からなくなったら戻ってきてください。

言葉意味
MapLibre GL 地図を表示するための JavaScript ライブラリ。Google マップのような地図を自分のアプリに埋め込めます。今回のバージョンは 6.8.0。
GeoJSON 地図の図形を表すための JSON の書き方の決まり。「点」「線」「面」などを表現できます。
LineString GeoJSON のうち線を表す種類。座標をつなぐ順番に並べたもの。ルートの線はこれで表します。
座標の順番 GeoJSON も MapLibre も [経度, 緯度] の順。日本人が言う「緯度・経度」と逆なので要注意です。
ワーカー
(Web Worker)		 ブラウザで裏側で別に動く処理係。重い計算をこちらに任せると、画面がカクつきません。MapLibre は線や図形の計算をワーカーに任せています。今回の主役です。
Vite フロントエンドのビルドツール。開発中はサーバーとして動き、公開時は配信用のファイル（dist）を作ります。
SPA Single Page Application。ページを切り替えても実際には 1 枚の HTML を使い回す作り。ミチシルもこれです。存在しない URL を頼まれると、代わりに index.html を返すという性質があり、これが今回の症状に関係します。
Pinia Vue で画面をまたいでデータを持ち回るための仕組み。作ったルートはここに保存しています。

3. データがどう流れているか

「ルート作成」ボタンを押してから線が描かれるまでの流れです。

① 画面条件を選ぶ
→
② Lambdaルートを作る
→
③ 変換画面用に整える
→
④ 保存Pinia に置く
→
⑤ 地図線を引く

② サーバー（Lambda）が返してくるもの

Lambda は Amazon Location Service に「この道をこう歩く」という経路を計算させ、 その座標を geometry として返します。実際のレスポンスはこんな形です。 

{
  "route_title": "新宿駅周辺ショッピング＆グルメ散歩コース",
  "concept_story": "新宿駅を起点に、東口の商業施設から…",
  "summary": { "total_distance_m": 2672, "total_duration_s": 4008 },
  "waypoints": [
    { "name": "BicCamera Shinjuku East Exit Store", "lng": 139.703, "lat": 35.69138 }
  ],
  "geometry": {
    "type": "LineString",
    "coordinates": [
      [139.703178, 35.686378],
      [139.702991, 35.687023],
      ...  ← 全部で 68 点
    ]
  }
}
ポイント：coordinates が線そのものです。この 68 個の点を順につなぐと、 道なりに曲がるルートの線になります。点が多いほどなめらかな線になります。

③ 画面用に整える（変換）

サーバーとフロントで書き方の決まりが違うので、境目で 1 か所にまとめて変換しています （frontend/src/utils/routeResponse.js）。

サーバーが返す形画面で使う形なぜ変えるか
route_titlerouteNameプロジェクトの決まりが camelCase のため
total_distance_m（メートル）distanceKm（キロ）画面は km で表示するため。名前に単位を入れて取り違えを防ぐ
total_duration_s（秒）durationMinutes（分）同上
waypointsspots「立ち寄る場所」と「線を描くための点」を混同しないため
なぜ名前を分けるのか（大事）
サーバーは立ち寄り先を waypoints という名前で返しますが、 ルート上には道の曲がり角の座標も何十個もあります。両方を同じ名前で扱うと、 「巡ったスポット数」に曲がり角まで数えて 2 のはずが 68 と表示される、という不具合が起きます。 エラーにならず数字だけが狂うので気付きにくい。だから 立ち寄り先は spots、線の点は geometry.coordinates と役割で名前を分けています。

⑤ 地図に線を引く

MapLibre では「データ」と「見た目」を別々に登録します（RouteMap.vue）。

// データを登録する（ソース）
map.addSource('route', { type: 'geojson', data: routeFeature });

// 見た目を登録する（レイヤー）。白い縁取りの上に青い本体を重ねる
map.addLayer({ id: 'route-line-outline', type: 'line', source: 'route',
  paint: { 'line-color': '#FFFFFF', 'line-width': 9 } });

map.addLayer({ id: 'route-line', type: 'line', source: 'route',
  paint: { 'line-color': '#1A73E8', 'line-width': 5 } });

白い線を先に太く引いて、その上に青い線を細く重ねています。こうすると地図の道路や公園に紛れず、線がはっきり見えます。

5. 「線が出ない」の調査記録

症状

  • 地図（背景の街の絵）は出る
  • スポットの番号付きの印は出る
  • ルートの線だけ出ない
  • 画面にエラーは出ない

外れた見立て① データの渡し方が悪いのでは？

Vue の Pinia に入れたデータは、変更を検知するために「プロキシ」という special な包み紙で包まれます。 一方 MapLibre はデータをワーカーへ送るとき構造化複製というコピーを行い、 この包み紙付きのデータはコピーに失敗します。

実際に試すと、たしかに失敗しました。

素のオブジェクト     : 成功
リアクティブなProxy  : 失敗 → DataCloneError: #<Object> could not be cloned.

「これだ」と思って素のデータに作り直す修正を入れました（855102b）。 しかし線は出ませんでした。現象自体は本物でしたが、今回の原因ではなかったのです。

外れた見立て② 緑で見づらいだけでは？

当初の線は緑（#4A7C59）で、地図の公園や緑地と色が近かったため 「細い線が背景に紛れているのでは」とも考えました。青に変えましたが（3de1ff1）、 やはり線は出ませんでした。

方針を変える：推測をやめて、実際の値を見る

2 回外したので、コードを読んで当てにいくのをやめ、実行時の値を出すことにしました（ce11141）。 具体的には次を画面のコンソールに出しました。

  • 座標が何点あるか／全部同じ座標になっていないか
  • 地図に登録されたレイヤーの一覧と順番
  • データとレイヤーが本当に存在するか
  • 実際に画面へ描かれた線の数

出てきた結果

[地図診断] 座標数 118
[地図診断] 座標がすべて同一か false
[地図診断] スタイルのレイヤー順 ['osm-raster', 'route-line-outline', 'route-line']
[地図診断] ソース有無 true
[地図診断] レイヤー有無 true

データも設定もすべて正常でした。座標は 118 点あり、同じ点の繰り返しでもなく、 レイヤーもきちんと地図の一番上に登録されている。それでも線が出ない。

決め手はコンソールの 1 行目

診断ログのすぐ上に、赤いエラーが出ていました。

Failed to load module script: The server responded with a non-JavaScript
MIME type of "text/html". Strict MIME type checking is enforced for
module scripts per HTML spec.
        /assets/maplibre-gl-worker.mjs

日本語にすると「JavaScript を読み込もうとしたら HTML が返ってきたので拒否した」です。 読み込もうとしたファイルは maplibre-gl-worker.mjs。 つまり地図のワーカーが起動できていなかったのです。

6. 本当の原因

何が起きていたか

順を追うとこうなります。

  1. MapLibre がワーカーのファイル /assets/maplibre-gl-worker.mjs を要求する
  2. ところがそのファイルはビルド結果に含まれていない
  3. SPA なので、存在しない URL には代わりに index.html（HTML）が返る
  4. ブラウザは「JavaScript を期待したのに HTML が来た」と判断して拒否する
  5. ワーカーが起動しない → 線の計算が行われない → 線が描かれない

実際、ビルド結果にワーカーがありませんでした。

修正前の dist/assets/
├── index-C-RabKC3.js
├── index-CNTuZ5Bt.css
└── logo-CyVFzEEQ.png     ← ワーカーのファイルが無い

なぜ含まれなかったのか

MapLibre のバージョン 6 から、ワーカーが別ファイルに分けられました。 そしてその URL を、次のように変数を使って組み立てています。 

// MapLibre の内部（読みやすく整えたもの）
const fileName = 開発版か ? 'maplibre-gl-worker-dev.mjs' : 'maplibre-gl-worker.mjs';
return new URL('./' + fileName, base).href;
ここが落とし穴です。 Vite は「どのファイルを配信用にコピーするか」を、コードを読んで判断します。 './maplibre-gl-worker.mjs' と直接書いてあれば気付けますが、 上のように変数で組み立てていると読み取れません。 結果「使われていないファイル」と見なされ、コピーされませんでした。

なぜ地図とスポットの印は出ていたのか

これが一番のヒントでした。同じ地図の上なのに、出るものと出ないものがあったのです。

要素結果通っている経路
地図の背景 出る ただの画像なので、画面本体のスレッドで読み込む。ワーカー不要
スポットの印 出る HTML の要素を地図の上にかぶせているだけ。ワーカー不要
ルートの線 出ない 座標から線の形を計算する必要があり、その計算をワーカーが担当している
教訓：「A は動くのに B は動かない」というときは、 A と B の違いは何かを考えると原因に近づけます。 今回は「ワーカーを使うかどうか」が違いでした。

7. どう直したか

MapLibre には、ワーカーの場所を自分で教えるための setWorkerUrl() という関数が用意されています。 そこで「Vite にワーカーを配信用ファイルとして作らせ、その URL を MapLibre に教える」ことにしました。 

// frontend/src/components/feature/route/RouteMap.vue

import { MapLibreMap, Marker, NavigationControl, Popup, setWorkerUrl } from 'maplibre-gl';

// Vite にワーカーとしてバンドルさせ、その URL を受け取る
import maplibreWorkerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url';

// 地図を作る前に一度だけ設定する
setWorkerUrl(maplibreWorkerUrl);

?worker&url という書き方について

Vite ではインポート先の末尾に ? で指示を付けると、扱い方を変えられます。

書き方意味今回使えるか
?url ファイルをそのままコピーして、その URL を返す ×
?worker&url 依存しているファイルもまとめて 1 つのワーカーとして組み立て、その URL を返す ○ これを採用

?url が使えないのは、ワーカーのファイルがさらに別のファイルを読み込んでいるからです。 単純にコピーしただけでは、その読み込み先が見つからず動きません。 ?worker&url なら必要なものを全部まとめてくれます。

もう 1 つ入れた備え

今回の失敗の一番やっかいだった点は、エラーが画面に出なかったことです。 ワーカーの中で起きた問題は、放っておくと何も表示されません。 そこで、地図のエラーを受け取って必ず記録するようにしました。 

map.on('error', (event) => {
  console.error('地図の描画に失敗しました', event.error ?? event);
});

これは調査用ではなく恒久的に残すコードです。同じ種類の問題が二度と黙って起きないようにするためです。

修正前はここで text/html（＝ index.html）が返っていました。 text/javascript になったことが、直った証拠です。

自分の環境で確かめる手順

  1. frontend フォルダで npm run dev を実行
  2. ホーム画面で Ctrl + Shift + R（ハードリロード）
  3. 条件を選んで「ルート作成」を押す
  4. 青い線が道なりに引かれていれば成功
ハードリロードが必要な理由
開発サーバーはコードの変更を自動で反映しますが、地図を作る処理は最初の 1 回だけ動きます。 自動反映では作り直されないため、古い地図が残ることがあります。 実際この調査中も、色（CSS）は反映されているのにプログラムは古いまま、という紛らわしい状態が起きました。
また、提案画面でリロードするとホーム画面に戻されます（ルート未取得の状態で直接開けない作りのため）。 必ずホーム画面でリロードしてください。

9. ここから学べること

① 「エラーが出ない」は「問題がない」ではない

今回は画面に何も出ませんでしたが、コンソールにはずっとエラーが出ていました。 うまく動かないときは、まず F12 の Console タブを見る習慣をつけてください。

② 推測で直すのは 2 回まで

今回は 2 回続けて原因を読み違えました。3 回目は推測をやめ、 実際の値を出して確かめる方針に切り替えたことで一気に解決しました。 当てにいく修正を重ねるより、状況を観測するコードを一時的に足すほうが早いです。

③ 動くものと動かないものの「違い」を探す

「地図は出るのに線は出ない」の差分が、そのまま原因（ワーカーを使うかどうか）でした。 全部動かないより、一部だけ動かないほうが実は手がかりが多いのです。

④ 新しいバージョンには落とし穴がある

今回の原因は MapLibre のバージョン 6 で入った変更（ワーカーの分離）でした。 ライブラリを最新にするときは、こうした構成の変更が起きていないか気にすると安全です。

⑤ SPA は 404 を隠してしまう

通常なら「ファイルが無い」は 404 で分かります。しかし SPA は存在しない URL に index.html を返すため、404 ではなく「中身が違う」という形で問題が現れます。 「HTML が返ってきた」というエラーを見たら、ファイルが無いことを疑ってください。
