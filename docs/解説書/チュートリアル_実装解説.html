🧩 先に知っておきたいこと

Pinia のストア
複数の画面から同じ値を読み書きするための「共有の入れ物」です。チュートリアルは ホーム → 提案 → 案内 → 結果の4画面をまたぐので、「今どの段階か」をストア（tutorialStore）に置いています。 ストアはメモリ上にあるだけなので、ブラウザを再読み込みするとチュートリアルの状態は消えます。
ダミーデータ
本物のAPIを呼ばずに、画面に見せるための作り物のデータです。チュートリアルでは ルート・口コミの場所・散歩の実績をすべて constants/tutorial.js の固定値で済ませ、AWS には一切通信しません。
pointer-events と disabled
CSS の pointer-events: none は「その要素をクリックできなくする」指定です。 ただし子要素側で pointer-events: auto が指定されていると子は押せてしまうため、 確実に止めたいボタンには HTML の disabled 属性を併用しています。
マスコットの吹き出し
各画面の案内役（フクロウ）が話す部品 MascotSpeechBubble です。チュートリアルの説明文もこの吹き出しで話させています。 部品の詳細は マスコットとファンタジー調デザイン を参照してください。

📖 この機能について

ホーム画面右上のメニューから「チュートリアル」を選ぶと、マスコットの案内に沿って ルート作成 → 決定 → 案内 → 口コミの評価 → 終了 → 結果 までを一通り体験できる機能です。 各段階では「今押してほしい要素」だけが操作でき、それ以外は淡く表示されて押せません。

チュートリアル中は本物のAPIを呼ばず、GPSでの現在地の追跡もしません。どこで誰が試しても、 同じダミーのルート（新宿駅周辺・スポット2か所・5km）で同じ流れをたどります。

🎯 なぜこの機能が必要？

ミチシルは「条件を選ぶ → ルートを確かめる → 歩きながら次へ進める → 口コミを残す → 結果を見る」と、 画面と操作が多いアプリです。初めての人が実際に外を歩きながら操作を覚えるのは大変なので、 室内でも安全に一通りの操作を練習できるようにしました。

チュートリアルがたどる流れは、前提条件書の画面遷移（US-1 → US-2 → US-3 → US-4/US-6 → US-7 → US-8）そのものです。 加えて口コミ（評価）の付け方も練習させます。

🔄 処理の流れ

段階（ステップ）は constants/tutorialSteps.js の配列の並び順で一本道に進みます。

#ステップ名画面利用者にさせる操作
1select-genreホームジャンルで「写真」を選ぶ
2select-distanceホーム距離スライダーをちょうど 5km に合わせる
3create-routeホーム「ルートを作成」を押す（APIは呼ばずダミールートを入れる）
4confirm-routeルート提案「決定」を押す
5advance-spot案内「次の目的地へ」を押す
6open-review案内地図の紫ピン（ダミーの口コミの場所）をタップする
7rate-review案内口コミフォームで★を付ける
8submit-review案内「投稿」を押す（実際には送信しない）
9request-end案内「終了」を押す
10confirm-end案内終了確認で「終了する」を押す
11return-home散歩結果「ホームに戻る」を押してチュートリアル完了
Step 1: 開始
SignOutMenu（ホーム右上のメニュー）の「チュートリアル」を押すと startTutorial が通知され、 RouteConditionView の handleStartTutorial が条件を初期化してから tutorialStore.start() を呼びます。 チュートリアル中のメニューは「チュートリアルを終了」に差し替わり、途中でやめられます。
Step 2: ホーム画面（1〜3）
フォーム（RouteConditionForm）は tutorialSection で「今触れる区画」を受け取り、 ジャンルの段階では「写真」以外のボタンとおまかせを無効にします。距離の段階ではスライダーが 5km で頭打ちになり、 ちょうど 5km になったときだけ次へ進みます。「ルートを作成」は作成の段階だけ押せます。
Step 3: ルート提案画面（4）
画面全体に暗い膜（tutorial-dim-overlay）を敷き、「決定」と吹き出しだけを膜の手前に出します。 「再作成」「ホームに戻る」はロックされます。
Step 4: 案内画面（5〜10）
現在地の追跡・口コミの取得（実API）を行わず、地図の操作（ドラッグ・拡大）も止めます。 紫ピンはダミーを1つだけ出し、タップの段階になると地図がそのピンへ滑らかに移動します。 口コミフォームではフォーム内の吹き出しが説明し、★→投稿の順に目立たせます。投稿は送信せず成功扱いにします。 終了の確認後は、実績の保存やレベルアップ判定を飛ばして結果画面へ進みます。
Step 5: 散歩結果画面（11）
総距離・スポット数・所要時間はダミーの固定値（5km・2か所・60分）を表示し、レベルアップ演出も出しません。 「ホームに戻る」で tutorialStore.finish() を呼び、チュートリアルを終えます。

💻 コードの解説

frontend/src/stores/tutorialStore.js

「チュートリアル中か」「今何番目のステップか」だけを持つ小さなストアです。

const completeStep = (step) => {
  if (!isActive.value || currentStep.value !== step) {
    return;
  }

  if (stepIndex.value < TUTORIAL_STEPS.length - 1) {
    stepIndex.value += 1;
  }
};
  • 入力: 完了したとみなすステップ名
  • 動き: 今のステップと一致したときだけ1つ進めます。順番を飛ばした操作では何も起きないので、一本道が崩れません
  • revertStep は逆に1つ戻します。案内画面で「前の目的地へ」を押したとき、open-review から advance-spot へ戻すために使います
  • isStep(step) は「今そのステップか」を返し、各画面がハイライト対象を決めるのに使います
  • ステップ名の定数を STEP として再公開しているので、画面側は tutorialStore.STEP.SELECT_GENRE のように書けます

frontend/src/constants/tutorialSteps.js / tutorial.js

tutorialSteps.js は「ステップ名・どの画面か・マスコットの文言」の表です。文言を変えたいときはここだけ直します。 tutorial.js はダミーデータ置き場で、主なものは次のとおりです。

名前中身
TUTORIAL_GENRE_ID / TUTORIAL_DISTANCE_KM選ばせるジャンル（photo）と距離（5km）
createTutorialRoute()ダミーのルート。画面用のルートの形（toRoute の戻り値と同じ）で、スポット2か所・区間（legs）3本を持つ。呼ぶたびに複製して返す
TUTORIAL_OTHER_REVIEW_SPOT地図に出すダミーの紫ピン（他の人の口コミの場所）
TUTORIAL_RESOLVED_REVIEW_SPOT紫ピンを押したときにフォームへ渡す「既存の場所」。作成者ではない（評価のみモード）
TUTORIAL_WALK_RESULT結果画面に出す固定の実績
export const createTutorialRoute = () => ({
  routeId: 'tutorial-route',
  routeName: 'はじめての写真さんぽ',
  ...
  spots: TUTORIAL_SPOTS.map((spot) => ({ ...spot })),
  ...
});

ストアへ入れたオブジェクトは画面から書き換えられることがあるため、元の定数を汚さないよう毎回コピーを返しています。

frontend/src/components/feature/tutorial/TutorialSpotlight.vue

中身を包んで「ロック（淡く・押せない）」か「ハイライト（そのまま）」を切り替えるだけの部品です。

<div
  class="tutorial-spotlight"
  :class="{
    'is-locked': isActive && !isHighlighted,
    'is-highlighted': isActive && isHighlighted
  }"
>
  <slot />
</div>
  • 通常は display: contents で、包んでいてもレイアウトに影響しません
  • ロック中は opacity: 0.4・pointer-events: none・少し灰色にします
  • 要素の位置を測らないので、端末の画面サイズが変わっても崩れません

frontend/src/components/base/BaseSlider.vue（valueMaxValue）

目盛りの上限（10km）は本番と同じに見せたまま、選べる値だけを 5km で止めるための props が追加されました。 

const handleInput = (event) => {
  const clamped = clampValue(Number(event.target.value));

  // つまみを頭打ちの位置へ戻す（ドラッグし続けても超えて見えないようにする）
  if (Number(event.target.value) !== clamped) {
    event.target.value = String(clamped);
  }

  emit('update:modelValue', clamped);
};

スライダーはドラッグ中もブラウザが内部でつまみを動かすため、値を親へ返すだけでは戻りきらない端末があります。 そこで input 要素の値そのものも書き戻して、つまみを押し戻しています。

frontend/src/views/RouteNavigationView.vue（案内画面）

チュートリアルの分岐がいちばん多い画面です。主な分岐は次のとおりです。

場所チュートリアル中の動き
onMountedstartTracking()・loadMyReviews()・loadReviewSpots() を呼ばない
otherReviewSpotsダミーの紫ピン1つだけを返す
showOtherReviews既定は非表示だが、チュートリアル中だけ表示で始める（紫ピンをタップさせる段階があるため）
isMapInteractive地図のドラッグ・拡大を止める（紫ピンのタップはマーカー自身が受けるので動く）
handleLongPressMap長押しによる新規投稿はさせない
sendReview送信せずに成功（true）を返す
handleConfirmEnd実績の保存・レベルアップ判定をせずに結果画面へ進む

⚠️ 注意ポイント

画面下に固定したボタンは TutorialSpotlight で包まない
ロック時に親へかかる filter が、position: fixed の基準を親に変えてしまい、ボタンの位置が崩れます。 ホームの「ルートを作成」は包まずに is-disabled で止めています。初期実装では全画面の膜と position: relative で浮かせていましたが、同じ理由で取りやめた経緯があります（62ae3dc / c1b34cf）。
新しい画面・操作を足すときはチュートリアルの分岐も確認する
実APIを呼ぶ処理を案内画面に足した場合、チュートリアル中に呼ばれないかを必ず確認してください。 呼ばれると、ダミーのルートIDで本物のAPIを叩くことになります。
「チュートリアル」は用語辞書に未登録
tutorial / TutorialSpotlight / tutorialStore などの語は naming-glossary.md にまだ載っていません。新しい語を足すときは、先に辞書への登録をチームで決めてください。

✅ 動作確認方法

  1. リポジトリのルートで npm run dev を実行し、フロントとローカルAPIを起動する
  2. ログインしてホーム画面を開き、右上のメニューから「チュートリアル」を選ぶ
  3. マスコットの指示に従い、「写真」→ 5km →「ルートを作成」→「決定」と進める。指示以外のボタンが押せないことを確かめる
  4. 案内画面で「次の目的地へ」→ 紫ピン → ★ →「投稿」→「終了」→「終了する」と進める。地図がドラッグできないこと、紫ピンへ自動で移動することを確かめる
  5. 結果画面に 5km・2か所・60分が出て、「ホームに戻る」で通常のホームへ戻ることを確かめる
  6. 途中でメニューの「チュートリアルを終了」を押し、条件が初期化されて通常のホームへ戻ることも確かめる
  7. 案内画面のテストは frontend で npm test（src/views/__tests__/RouteNavigationView.test.js にチュートリアル中の口コミピン表示の確認がある）
