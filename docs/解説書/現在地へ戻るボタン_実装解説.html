現在地へ戻るボタン - 実装解説

🗓 対象期間: 2026-10-01 〜 2026-10-07
📅 マージ日: 2026-10-07（10:55 / 12:20 の2回）
🌿 対象ブランチ: feature/NZ-233（2回に分けてマージ）
🔖 対象マージ: cad1042, cc02d5c

案内画面の地図に「現在地へ戻る」ボタンを追加しました。地図を指で動かして現在地が画面外へ出てしまっても、 ボタンを1回押すだけで現在地が中央に戻り、拡大率（ズーム）も最初に表示していた状態に戻ります。 変更したのはフロントエンドの2ファイルだけで、バックエンドやAWSの構成には手を入れていません。

🧩 先に知っておきたいこと

MapLibre GL とは
ミチシルで地図を描いている JavaScript のライブラリです。地図の中心座標や拡大率を指示すると、 タイル（地図の画像データ）を並べて描画してくれます。ミチシルでは frontend/src/components/feature/route/RouteMap.vue がこのライブラリを扱う唯一の場所です。
「コントロール」とは
MapLibre GL が地図の隅に置く小さな操作パネルのことです。ミチシルでは右上に「＋」「−」のズームボタンが出ていますが、 これも NavigationControl というコントロールです。ライブラリが決めた形（onAdd / onRemove を持つオブジェクト）に合わせて自作すると、 既存のボタンと同じ枠・同じ見た目で並べられます。今回の現在地へ戻るボタンはこの仕組みで追加しています。
現在地はどこから来るか
現在地の測位（GPSなどで位置を取ること）はこの機能では行っていません。案内画面が useLocationTracking という composable で測位を続け、その結果を地図コンポーネントへ渡しています。 詳しくは 現在地取得機能の実装解説 を参照してください。
<style scoped> が届かない場所がある
Vue の <style scoped> は、そのコンポーネントが描いた要素だけにスタイルを当てる仕組みです。 MapLibre GL はコントロールやマーカーをコンポーネントの外側のDOMへ挿入するため、scoped のスタイルが当たりません。 そのため、地図に挿入される部品のスタイルは frontend/src/assets/styles/global.css に置いています。
props（プロパティ）の受け渡し
親コンポーネントから子へ値を渡す仕組みです。今回の実装では showCurrentLocation（現在地を表示するか）と isInteractive（地図の操作を許可するか）という 2つの props を見て、ボタンを出すかどうかを決めています。

📖 この機能について

案内画面（RouteNavigationView.vue）の地図の右上、ズームボタンのすぐ下に、丸いアイコンのボタンが1つ増えます。 押すと次の2つが同時に起こります。

  • 地図の中心が現在地へ移動する
  • 拡大率が「画面を開いた直後の見え方」に戻る

このボタンは案内画面にだけ出ます。ルート提案画面の地図は RouteMapPreview.vue 経由で isInteractive を false（操作不可）にしているため、 ズームボタンも現在地へ戻るボタンも表示されません。

機能は2回のマージに分かれています。1回目（cad1042）でボタンそのものを追加し、 2回目（cc02d5c）で「拡大率も戻す」挙動を足しました。

🎯 なぜこの機能が必要？

案内中（US-6「案内画面表示」）は、歩きながら地図を指でずらしたり、先のスポットを確かめるために縮小したりします。 その結果、自分の現在地が画面の外へ出てしまうことがあります。ミチシルの地図は現在地を自動で追いかけ続ける作りではないため、 一度ずらすと、自分で地図をドラッグして現在地を探し直すしかありませんでした。歩きながらの操作としては手間が大きく、 「今どこにいるか」が分からない時間ができてしまいます。

そこで、1回押せば現在地に戻れる手段を用意しました。地図アプリで一般的な操作なので、使い方の説明も要りません。

拡大率も戻すようにした理由: 1回目のマージ（cad1042）の時点では、コードのコメントに 「ズーム倍率は変えず、位置だけを移動させる」と書かれているとおり、中心座標だけを動かしていました。 しかし拡大率が変わったままだと、たとえばルート全体を見るために大きく縮小した状態でボタンを押しても、 現在地が中央に来るだけで縮小されたままです。周りの道が見える元の縮尺に戻すには、さらにズーム操作が必要でした。 2回目のマージ（cc02d5c）で拡大率の復元を足し、ボタン1回で最初の見え方に戻るようにしています。

🔄 処理の流れ

Step 1: 地図を作り、ルート全体を収める（cad1042 以前からある処理）
画面を開くと onMounted で地図が生成され、スタイルの読み込みが終わった時点（map.on('load')）で 線やマーカーを描き、最後に fitToRoute() でルート全体が収まる位置・倍率まで地図を寄せます。
Step 2: 初期表示の拡大率を覚える（cc02d5c で追加）
fitToRoute() の最後に map.getZoom() で寄せ終わった倍率を読み取り、 initialZoomLevel という変数に保存します。これが「最初の見え方」の基準になります。
Step 3: 測位が始まったらボタンを追加する（cad1042）
現在地マーカーを描く renderCurrentLocationMarker() の先頭で ensureRecenterControl() を呼びます。 この関数は、まだボタンが無く・地図が操作可能で・現在地の表示が有効なときだけ、コントロールを地図の右上へ追加します。
Step 4: ボタンが押されたら現在地へ寄せる（cad1042 + cc02d5c）
クリックで centerOnCurrentLocation() が動き、map.easeTo() に現在地の座標と initialZoomLevel を渡します。easeTo は瞬間移動ではなく、なめらかに動かす指示です。
Step 5: 画面を離れるときの片付け（cad1042）
onBeforeUnmount で recenterControl の参照を null に戻します。 コントロール自体は map.remove() が破棄するため、個別に外す処理は書いていません。

💻 コードの解説

frontend/src/components/feature/route/RouteMap.vue — 現在地へ寄せる関数

ボタンを押したときに実行される処理です。zoom の行が2回目のマージで足された部分です。

/**
 * @description 地図の中心を現在地へ寄せ、拡大率を初期表示と同じに戻す。
 * @returns {void}
 */
const centerOnCurrentLocation = () => {
  if (map === null || props.currentLocation === null) {
    return;
  }

  map.easeTo({
    center: [props.currentLocation.lng, props.currentLocation.lat],
    zoom: initialZoomLevel
  });
};
  • 入力: なし（props.currentLocation とモジュール内の initialZoomLevel を参照します）。出力: なし。
  • 地図がまだ無いとき、現在地が取れていないときは何もせずに抜けます。押しても落ちないようにするためのガードです。
  • center に渡す座標は [経度, 緯度] の順です。地図ライブラリの決まりで、緯度が先ではありません。

RouteMap.vue — 初期表示の拡大率を覚える

拡大率を戻すには「戻す先の値」が必要です。その値は、ルート全体を収めた結果として決まるので、 収め終わった直後に読み取って保存しています。 

/**
 * 初期表示の拡大率。
 * ルート全体を収めた直後の値を覚えておき、現在地へ戻るときに復元する。
 * 地図の生成時の値を初期値とし、ルートを収められない場合もこの値を使う。
 */
let initialZoomLevel = DEFAULT_ZOOM_LEVEL;
  map.fitBounds(bounds, {
    padding: MAP_FIT_PADDING_PX,
    maxZoom: MAX_FIT_ZOOM_LEVEL,
    animate: false
  });

  // 現在地へ戻るときに初期表示と同じ倍率へ復元できるよう、この時点の倍率を覚えておく。
  // animate: false のため、ここでは寄せ終わった後の値が取れる
  initialZoomLevel = map.getZoom();
  • 初期値は frontend/src/constants/mapDefaults.js の DEFAULT_ZOOM_LEVEL（14）です。 経路の座標が無くて fitToRoute() が途中で抜ける場合は、この値が使われます。
  • animate: false は「アニメーションせずに即座に寄せる」指定です。これがあるので、 直後の map.getZoom() で寄せ終わった後の倍率が取れます。アニメーションする設定だと、 移動中の途中の値を拾ってしまいます。
  • initialZoomLevel は ref ではなく素の変数です。画面に表示する値ではなく、 地図ライブラリへ渡すだけの内部的な値なので、Vue の監視対象にする必要がありません （同じ理由で map や各マーカーも素の変数で持っています）。

RouteMap.vue — ボタンを組み立てる

MapLibre GL のコントロールとして渡せる形（onAdd / onRemove を持つオブジェクト）を自作しています。

const createRecenterControl = () => {
  const container = document.createElement('div');
  container.className = 'maplibregl-ctrl maplibregl-ctrl-group';

  const button = document.createElement('button');
  button.type = 'button';
  button.className = 'recenter-btn';
  // アイコンのみのボタンなので、読み上げ用の名前を付ける
  button.setAttribute('aria-label', RECENTER_BUTTON_LABEL);
  button.title = RECENTER_BUTTON_LABEL;
  button.addEventListener('click', centerOnCurrentLocation);

  container.appendChild(button);

  return {
    onAdd: () => container,
    onRemove: () => {
      button.removeEventListener('click', centerOnCurrentLocation);
      container.remove();
    }
  };
};
  • maplibregl-ctrl maplibregl-ctrl-group はライブラリが用意しているクラス名です。 これを付けるだけで、ズームボタンと同じ白い角丸の枠・同じ大きさになります。
  • アイコンだけのボタンなので、aria-label に「現在地へ戻る」という名前を付けています （画面読み上げソフトのための名前です。定数 RECENTER_BUTTON_LABEL にまとめ、title にも同じ文字列を使っています）。
  • onRemove でクリックの登録を外しています。登録したまま要素を捨てると、 参照が残り続けてメモリを解放できなくなる場合があるためです。

RouteMap.vue — 追加するタイミングの判定

ボタンの追加は地図の生成時ではなく、現在地マーカーを描くときに行っています。

/**
 * @description 現在地へ戻るコントロールを必要になった時点で追加する。
 *
 * 追跡の開始は親（View）のonMountedで行われ、子のonMountedより後になる。
 * 地図の生成時には現在地の表示が無効のままなので、ここで追加する。
 * @returns {void}
 */
const ensureRecenterControl = () => {
  if (
    recenterControl !== null ||
    map === null ||
    !props.isInteractive ||
    !props.showCurrentLocation
  ) {
    return;
  }

  recenterControl = createRecenterControl();
  map.addControl(recenterControl, 'top-right');
};
条件追加しない理由
recenterControl !== nullすでに追加済み。現在地は何度も更新されるので、毎回作るとボタンが増えてしまう
map === null地図がまだ無い、または破棄済み
!props.isInteractive操作できない地図（ルート提案画面のプレビュー）にはズームボタンも出していない
!props.showCurrentLocation現在地を表示していない画面では、戻る先が無いのでボタンに意味がない

Vue では子コンポーネントの onMounted が親より先に動きます。測位を始めるのは親の案内画面なので、 地図を作る時点では showCurrentLocation がまだ false です。 そのため「地図を作るときに1回だけ追加する」書き方では、ボタンが永遠に出ません。 現在地が届いて renderCurrentLocationMarker() が呼ばれた時点で追加するのが、この関数の役割です。

frontend/src/assets/styles/global.css — アイコンの見た目

ボタンの枠と大きさはライブラリの .maplibregl-ctrl-group が与えるので、ここでは中のアイコンだけを描いています。 画像ファイルは使わず、CSSで二重丸（紫の円の内側に白い輪、中心に紫の点）を作っています。 

.recenter-btn::after {
  content: '';
  display: block;
  width: 18px;
  height: 18px;
  margin: 0 auto;
  border: 2px solid var(--primary-color);
  border-radius: 50%;
  box-shadow: inset 0 0 0 3px var(--white);
  background: var(--primary-color);
  background-clip: content-box;
  padding: 3px;
  box-sizing: border-box;
}
  • 色は直書きせず var(--primary-color)（紫のインク）と var(--white) を参照しています。 配色は global.css の :root に集約する、という前提条件書の決まりに従っています。
  • ::after は要素の中に装飾用の箱を1つ作る書き方です。中心の点は background-clip: content-box と padding の組み合わせで、背景を内側だけに描いて表現しています。

⚠️ 注意ポイント

ボタンは「現在地を追い続ける」機能ではない
押した瞬間に1回だけ寄せるだけで、その後に歩いても地図は追従しません。常に追従させる挙動が必要なら、 別途そのための仕組み（追従のオン・オフ）を設計する必要があります。
現在地が取れていないと何も起きない
位置情報の許可が出ていない、測位に失敗しているといった場合、currentLocation が null のため 押しても地図は動きません。ボタン自体は showCurrentLocation（案内画面では測位中かどうか）が真なら表示されるので、 「押せるのに反応しない」状態が起こり得ます。
戻る先の拡大率はルートごとに変わる
initialZoomLevel は fitToRoute() が走ったときの倍率です。 ルートを再作成（regenerate）すると fitToRoute() が再び呼ばれるため、 新しいルートに合わせた倍率へ更新されます。固定値ではない点に注意してください。
スタイルを <style scoped> に移さない
.recenter-btn のスタイルは、地図ライブラリがコンポーネントの外へ挿入する要素に当てるものです。 RouteMap.vue の <style scoped> へ移すと当たらなくなり、アイコンが消えます。

✅ 動作確認方法

  1. リポジトリのルートで npm run dev を実行します（フロントとローカルAPIが同時に起動します）。
  2. ホーム画面で条件を選んでルートを作成し、提案モーダルで「決定」を押して案内画面へ進みます。
  3. 位置情報の利用を許可し、現在地の青い丸が表示されることを確認します。
  4. 地図の右上、ズームボタンの下に二重丸のボタンが出ていることを確認します。
  5. 地図を指（マウス）でドラッグして現在地を画面の外へ出し、さらに縮小します。
  6. ボタンを押し、現在地が中央に戻り、かつ拡大率が案内画面を開いた直後の状態に戻ることを確認します。
  7. ルート提案画面の地図（プレビュー）には、ズームボタンもこのボタンも出ないことを確認します。
  8. frontend/ で npm run lint と npm run build を実行し、エラーが出ないことを確認します。

この機能には自動テストを追加していません。地図ライブラリのDOM操作が中心のため、確認は上記の手動操作で行います。
