📝 課題番号: NZ-186

📖 この機能について

パスワードを忘れた人が、自分で新しいパスワードを決め直せる画面（/password-reset）を追加しました。ログイン画面の「パスワードの再設定」リンクから開けます。

手順は2段です。① ユーザー名を入れて確認コードをメールで受け取る → ② 届いた6桁のコードと新しいパスワードを入れる。終わるとログイン画面に戻り、「パスワードを再設定しました」と表示されます。

ログインの仕組み（Cognito と Amplify）の基本は docs/Cognitoログイン画面_構築手順書.html にまとまっています。ここでは再設定に関係する部分だけを説明します。

🎯 なぜこの機能が必要？

  • これまではパスワードを忘れると、管理者に頼むしかありませんでした。
  • 自分で再設定できれば、管理者の手間も利用者の待ち時間もなくなります。

「再発行」ではなく「再設定」と呼ぶ理由

Cognito（AWS のログイン機能）は、新しいパスワードを作って送ってくれるわけではありません。本人確認のコードだけを送り、新しいパスワードは利用者自身に決めさせます。そのため、コード上も画面上も「再設定（resetPassword）」で統一しています。forgotPassword や reissuePassword は使いません（naming-glossary.md の「認証」節）。

🔄 処理の流れ

[ログイン画面] 「パスワードの再設定」を押す
     ▼
[PasswordResetView 1段目] ユーザー名を入力
     │  authStore.resetPassword → authService.sendPasswordResetCode
     │  → Cognito の resetPassword（確認コードをメール送信）
     ▼
[PasswordResetView 2段目] 確認コード + 新しいパスワードを入力
     │  authStore.confirmResetPassword → authService.confirmPasswordResetWithCode
     │  → Cognito の confirmResetPassword（パスワードを変更）
     ▼
[ログイン画面] /login?reset=1 → 「パスワードを再設定しました」
Step 1: ユーザー名を送る
PasswordResetRequestForm.vue がユーザー名（前後の空白は取り除く）を親に渡します。画面（View）がストアの resetPassword を呼び、成功したら2段目に切り替えます。コードの送り先は、登録時に確認済みのメールアドレスです。こちらからは指定できません。
Step 2: コードと新しいパスワードを送る
PasswordResetConfirmForm.vue に、送り先（例: a***@example.com のように一部が隠された形）を表示します。コードと新しいパスワードを入れて送ると、ストアの confirmResetPassword が呼ばれます。
Step 3: ログイン画面に戻る
成功したら router.push({ name: 'login', query: { reset: '1' } }) で戻ります。ログイン画面は URL の reset=1 を見て完了メッセージを出します。
（任意）コードの再送
「確認コードを再送する」を押すと、1段目と同じ resetPassword をもう一度呼びます。Cognito では再送も「再設定の開始」と同じ操作だからです。

💻 コードの解説

frontend/src/services/authService.js — Cognito を呼ぶ

export const sendPasswordResetCode = async (username) => {
  const { nextStep } = await cognitoResetPassword({ username });

  if (nextStep.resetPasswordStep === 'CONFIRM_RESET_PASSWORD_WITH_CODE') {
    return nextStep.codeDeliveryDetails?.destination ?? null;
  }
  // コード入力を伴わない設定（DONE）は想定していないため、失敗として返す
  ...
};
  • 入力: ユーザー名。出力: コードの送り先（隠された形）。
  • Amplify（aws-amplify/auth）の関数は、このファイルの中だけで使います。ほかのファイルは Amplify を直接知らなくて済みます。
  • 「次はコードを入力してね」（CONFIRM_RESET_PASSWORD_WITH_CODE）以外が返ってきたら、想定外として失敗扱いにします。

confirmPasswordResetWithCode(username, confirmationCode, newPassword) は Cognito の confirmResetPassword をそのまま呼びます。

エラー文言の決め方

export const toPasswordResetErrorMessage = (error) =>
  PASSWORD_RESET_ERROR_MESSAGES[error?.name] ??
  ERROR_MESSAGES[error?.name] ??
  PASSWORD_RESET_DEFAULT_ERROR_MESSAGE;

Cognito のエラー名から、画面に出す日本語を3段階で探します。① 再設定専用の文言 → ② ログインなどと共通の文言 → ③ どれにも当てはまらないときの文言。

エラー名画面の文言補足
UserNotFoundExceptionユーザー名を確認してください「そのユーザーはいません」と言うと、第三者に登録の有無を知られてしまうため、あいまいにしている
InvalidParameterExceptionメールアドレスが未確認のため再設定できません…メールが確認されていないと、コードの送り先がない
CodeMismatchException確認コードが違います共通の文言
ExpiredCodeException確認コードの有効期限が切れています…共通の文言
InvalidPasswordExceptionパスワードの条件を満たしていません…共通の文言

frontend/src/stores/authStore.js

resetPassword と confirmResetPassword を追加しました。どちらも通信中は isResettingPassword を true にし、失敗したら errorMessage に文言を入れます。画面はこの2つを見て、ボタンを押せなくしたりエラーを表示したりします。

frontend/src/views/PasswordResetView.vue

  • isConfirming（2段目に進んだか）で、どちらのフォームを出すか切り替えます。
  • 対象のユーザー名（targetUsername）はこの画面の中だけで使うので、ストアではなく画面で持ちます。
  • 開いたときに authStore.clearErrorMessage() を呼び、ログイン画面で出ていたエラーを持ち込まないようにしています。

フォーム部品（PasswordResetRequestForm / PasswordResetConfirmForm）

  • 入力を受け取って親に渡すだけで、通信はしません（通信は View → ストア → service の順）。
  • 確認コード欄は inputmode="numeric"（スマホで数字キーボード）と autocomplete="one-time-code"（メールやSMSのコードを自動入力候補に出す）を指定しています。
  • 新しいパスワード欄は autocomplete="new-password" で、ブラウザのパスワード生成機能が使えます。
  • コードの桁数・パスワードの条件は constants/authValidation.js の定数を使います。

frontend/src/router/index.js

/password-reset（ルート名 password-reset）を追加し、meta: { isPublic: true } で未ログインでも開けるようにしました。ログイン済みで開くとホームへ送られます。

⚠️ 注意ポイント

パスワードの条件は2か所にある
画面のヒント（constants/authValidation.js）と、実際のルール（iac/lib/michishiru-stack.ts のユーザープールの passwordPolicy）は別々に書かれています。片方だけ変えると食い違うので、必ず両方を直してください。
存在しないユーザー名でもエラーにならないことがある
アプリクライアントは preventUserExistenceErrors: true（ユーザーの有無を伏せる設定）です。この設定だと、存在しないユーザー名でも Cognito が成功に見える応答を返すことがあり、その場合は2段目に進みますがメールは届きません。動作確認ではこの点を想定しておいてください。
メール確認が済んでいないユーザーは再設定できない
ユーザー登録で確認コードを入れずに終わったユーザーは、送り先のメールが「未確認」のままなので再設定できません。

✅ 動作確認方法

  1. Cognito の接続情報を用意します。ローカルでは frontend/.env.local に VITE_COGNITO_USER_POOL_ID と VITE_COGNITO_USER_POOL_CLIENT_ID を書きます（書き方は構築手順書を参照。値はチームの dev 環境のものを使い、コミットしないこと）。
  2. リポジトリのルートで npm run dev を実行します。
  3. ログイン画面の「パスワードの再設定」を押し、メール確認済みのユーザー名を入れて「確認コードを送る」を押します。
  4. メールに届いた6桁のコードと、新しいパスワードを入れて「パスワードを再設定する」を押します。
  5. ログイン画面に「パスワードを再設定しました」と出ること、新しいパスワードでログインできることを確認します。
  6. わざとコードを間違えて「確認コードが違います」と出ることも確認します。
  7. frontend/ で npm run lint と npm run build を実行します（フロントの自動テストは未導入です）。
