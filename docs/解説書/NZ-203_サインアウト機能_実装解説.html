NZ-203 サインアウト（ログアウト）機能 - 実装解説

📅 マージ日: 2026-09-30（14:40、PR #56、マージコミット db7756f）
🌿 ブランチ: feature/NZ-203
📝 課題番号: NZ-203
🧩 概要: ホーム画面（情報入力画面）の右上にハンバーガーメニューを置き、そこから「ログアウト」できるようにした

📖 この機能について

ログイン中の利用者が、ホーム画面の右上にある「≡」の形のボタン（ハンバーガーメニュー）を押すと、 「ログアウト」という項目が出てきます。これを押すと、ログイン状態が解除されてログイン画面に戻ります。

画面に出る文言は「ログアウト」ですが、コードの中では signOut（サインアウト）という名前で統一しています。 ログイン認証に使っている Amazon Cognito（アマゾン コグニート。AWS のログイン管理サービス）と、 それを呼び出すライブラリ Amplify の関数名が signOut だからです。 用語辞書（naming-glossary.md）でも logout は使わないと決められています。

🎯 なぜこの機能が必要？

  • これまではログインはできても、ログアウトする手段が画面にありませんでした。
  • 1台の端末を複数人で使う場合、前の人のログイン状態のまま次の人が使ってしまいます。
  • 前の人が入力したジャンルや距離、作ったルートが残っていると、次の人に見えてしまいます。そのため、ログアウト時にこれらも消しています。

🔄 処理の流れ

[ホーム画面 RouteConditionView]
   │  右上の「≡」ボタンを押す
   ▼
[SignOutMenu] メニューが開く ─→「ログアウト」を押す
   │  メニューを閉じて、親へ signOut イベントを通知
   ▼
[RouteConditionView] handleSignOut()
   ├─ ① authStore.signOut()        … Cognito からサインアウト、ログイン情報を空に
   ├─ ② routeStore.resetConditions() … 入力条件とルートを初期状態に
   └─ ③ router.push({ name: 'login' })
   ▼
[ルーターガード] 未ログインなのでログイン画面の表示を許可
   ▼
[ログイン画面 LoginView]
Step 1: 利用者がホーム画面右上の「≡」ボタンを押すと、SignOutMenu の中の isOpen（開いているかどうか）が true になり、「ログアウト」の項目が表示されます。
Step 2: 「ログアウト」を押すと、SignOutMenu はまずメニューを閉じ、親の画面へ signOut という合図（イベント）を送ります。メニュー自身はログアウト処理をしません。
Step 3: 親の RouteConditionView が合図を受け取り、handleSignOut を実行します。authStore.signOut() で Cognito からサインアウトし、ストアのユーザー名を空（null）にします。
Step 4: routeStore.resetConditions() で、ジャンル・距離・「おまかせ」の選択・取得済みのルートを初期状態に戻します。
Step 5: router.push({ name: 'login' }) でログイン画面へ移ります。画面を移る前に必ず通る見張り役（ルーターガード router.beforeEach）は、ログイン画面を「未ログインでも開ける画面」として扱っているので、そのまま表示されます。

💻 コードの解説

frontend/src/components/feature/auth/SignOutMenu.vue（新規）

ハンバーガーメニューの見た目と、開く・閉じるの動きだけを担当する部品です。 「ログアウトの処理そのもの」は持たず、押されたことを親へ知らせるだけにしています。 こうしておくと、部品はほかの画面でも使い回しやすく、処理の中身は画面側で決められます。 

const emit = defineEmits(['signOut']);

const handleSignOut = () => {
  closeMenu();
  emit('signOut');
};

emit は「子の部品から親へ合図を送る」Vue の仕組みです。 先にメニューを閉じておくのは、あとでこの画面に戻ってきたときにメニューが開いたままにならないようにするためです。

メニューを閉じる方法は3つあります。

操作 担当する関数 説明
「≡」ボタンをもう一度押す toggleMenu 開いていれば閉じ、閉じていれば開く
メニューの外側を押す handleOutsideClick 押された場所がメニューの中（menuContainer）でなければ閉じる
Esc キーを押す handleKeydown 押されたキーが Escape なら閉じる 
onMounted(() => {
  document.addEventListener('click', handleOutsideClick);
  document.addEventListener('keydown', handleKeydown);
});

onBeforeUnmount(() => {
  document.removeEventListener('click', handleOutsideClick);
  document.removeEventListener('keydown', handleKeydown);
});

画面のどこを押しても気付けるよう、ページ全体（document）に見張り（イベントリスナー）を付けています。 onMounted は「部品が画面に出たとき」、onBeforeUnmount は「部品が画面から消える直前」に動きます。 消える直前に見張りを外さないと、画面を移ったあとも見張りが残り続けてしまう（メモリリーク）ため、必ず対にしています。

アクセシビリティ（誰でも使えるための工夫）

<button
  type="button"
  aria-label="メニュー"
  aria-haspopup="true"
  :aria-expanded="isOpen"
  aria-controls="signout-menu-list"
  @click="toggleMenu"
>

aria- で始まる属性は、画面読み上げソフト（スクリーンリーダー）に情報を伝えるためのものです。

属性 意味
aria-label="メニュー" 「≡」は線の絵だけで文字がないため、「メニュー」ボタンだと読み上げさせる
aria-haspopup="true" 押すと何かが出てくるボタンだと伝える
:aria-expanded="isOpen" 今メニューが開いているか閉じているかを伝える（isOpen に合わせて自動で変わる）
aria-controls このボタンがどの一覧（id="signout-menu-list"）を開閉するかを結び付ける
aria-hidden="true"（3本の線） 飾りの線を読み上げの対象から外す

ボタンは本物の <button> 要素なので、Tab キーで移動し Enter / Space キーで押せます。 Esc キーでメニューを閉じることもできます。

frontend/src/views/RouteConditionView.vue（変更）

ホーム画面に SignOutMenu を置き、合図を受けたときの処理 handleSignOut を追加しました。

<SignOutMenu
  class="header-menu"
  @sign-out="handleSignOut"
/>

子の部品では signOut（camelCase）と宣言していますが、親のテンプレートでは @sign-out（kebab-case）と書きます。 「JavaScript の中は camelCase、HTML として書く場所は kebab-case」という Vue のルールです。 また .header-menu に margin-left: auto を付け、ロゴの右側の余白へ押し出してヘッダー右上に置いています。 

const handleSignOut = async () => {
  await authStore.signOut();
  routeStore.resetConditions();

  router.push({ name: 'login' });
};

await は「前の処理が終わるまで待つ」という意味です。サインアウトが終わってからログイン画面へ移るので、 ルーターガードが「まだログイン中」と勘違いしてホームへ戻してしまうことを防げます。 画面の移動先はパス（/login）ではなく名前（'login'）で指定しています（チームのルール）。

呼び出している既存の処理

この機能で新しく作ったのは画面側だけで、サインアウトの本体はもともとあった処理を使っています。

場所 関数 していること
stores/authStore.js signOut signOutFromCognito() を呼んだあと、username と errorMessage を null にする。username が null になると isSignedIn（ログイン済みかどうか）が自動で false になる
services/authService.js signOutFromCognito Amplify の signOut（aws-amplify/auth）を呼び、ブラウザに保存されているログインの証明書（トークン）を捨てる
stores/routeStore.js resetConditions genre / genreName を null、distanceKm を初期値、isGenreRandom / isDistanceRandom を false、currentRoute を null に戻す。散歩結果画面の「ホーム画面」ボタンでも使われている
router/index.js router.beforeEach ログイン画面は meta: { isPublic: true }。未ログインならそのまま表示し、ログイン済みならホームへ送る。逆にログインが必要な画面を未ログインで開くとログイン画面へ送る

「ストア」は Pinia（ピニア）というライブラリで作った、複数の画面で共有する入れ物です。 ログイン状態（authStore）と入力条件・ルート（routeStore）がそれぞれ入っています。

⚠️ 注意ポイント

ログアウトできるのはホーム画面だけ
メニューは RouteConditionView にだけ置かれています。ルート提案・案内・散歩結果の画面からはログアウトできません。
失敗したときの処理がない
handleSignOut には try / catch（失敗したときの受け止め）がありません。 authStore.signOut() の途中で例外が起きると、条件の初期化とログイン画面への移動が行われず、利用者には何も起きないように見えます。 必要なら、失敗時にトーストでメッセージを出すなどの対応を検討してください。
ログアウトはこの端末だけ
Amplify の signOut() を引数なしで呼んでいるため、この端末（ブラウザ）のログイン情報だけが消えます。 ほかの端末でログインしている分まで一度に切りたい場合は signOut({ global: true }) が必要です。
アクセシビリティの改善余地
  • メニューを開いても、キーボードの位置（フォーカス）は「≡」ボタンのままです。Tab キーを押すと「ログアウト」へ移れますが、矢印キーでの移動はありません。
  • Esc キーやメニュー外の押下で閉じたとき、フォーカスを「≡」ボタンへ戻す処理はありません。
  • aria-haspopup="true" は「メニュー（role="menu"）が出る」という意味ですが、一覧は普通の <ul> で role="menu" はありません。 今の作りに合わせるなら aria-haspopup を外して「開閉するだけのボタン」として扱うか、逆に role="menu" / role="menuitem" と矢印キー操作をそろえるか、どちらかに寄せると読み上げと動きが一致します。
  • id="signout-menu-list" は固定の値なので、1つの画面にこの部品を2つ置くと id が重複します。
なお、実際に読み上げソフトで使いやすいかどうかは、支援技術を使った手動の確認が必要です。

✅ 動作確認方法

画面での確認

  1. リポジトリのルート（michishiru_app/）で npm run dev を実行し、フロントとAPIを同時に起動する。
  2. ブラウザで表示されたURLを開き、ログイン画面からログインする（ホーム画面が表示される）。
  3. ジャンルや距離を選んでおく。
  4. 右上の「≡」ボタンを押し、「ログアウト」が出ることを確認する。もう一度押す・外側を押す・Esc キーを押すと閉じることも確認する。
  5. 「ログアウト」を押し、ログイン画面に移ることを確認する。
  6. ブラウザのアドレス欄にホーム画面のURL（/）を入力しても、ログイン画面へ戻されることを確認する。
  7. もう一度ログインし、前に選んだジャンルや距離が初期状態に戻っていることを確認する。
  8. キーボードだけで操作できるか確認する（Tab で「≡」へ移動 → Enter で開く → Tab で「ログアウト」へ → Enter）。

チェックコマンド

  1. frontend/ で npm run lint（書き方のチェック。ESLint）を実行し、エラーがないこと。
  2. frontend/ で npm run build（本番用ファイルの作成）を実行し、成功すること。

フロントエンドの自動テストはツールが未決定のため、この機能のテストコードはありません。
