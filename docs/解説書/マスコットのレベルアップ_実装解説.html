🧩 先に知っておきたいこと

マスコット（フクロウ）と吹き出し
各画面に1体だけ出てくる案内役です。表示部品（MascotAvatar / MascotSpeechBubble）の作りは マスコットとファンタジー調デザイン で説明しています。 この解説書は、その姿を実績に応じて Lv.1〜Lv.10 へ育てる仕組みを扱います。
累計の実績
散歩を終えると、その回の距離と時間がサーバー（DynamoDB の WalkResult-<環境> テーブル）の累計へ足されます。 足す仕組みは 散歩実績の保存 を参照してください。レベルはこの累計と口コミの投稿件数から決まります。
純関数
同じ入力には必ず同じ出力を返し、外の状態を書き換えない関数です。経験値とレベルの計算は utils/mascotLevelProgress.js の純関数にまとめてあり、Vue を使わずにテストできます。
Pinia のストア
画面をまたいで値を共有する入れ物です。レベルはホーム・ロード・提案・案内・結果の各画面で使うので、 mascotStore に1つだけ持たせています。

📖 この機能について

利用者の実績（口コミの投稿件数・歩いた累計距離・歩いた累計時間）を経験値に換算し、 マスコットのレベル（1〜10）と次のレベルまでの進み具合（経験値バー）を表示する機能です。 散歩を終えてレベルが上がった場合は、散歩結果画面の前に全画面の「レベルアップ！」演出を見せます。

実績経験値
口コミの投稿 1件100
歩いた距離 1km100
歩いた時間 1分10

次のレベルまでに必要な経験値は Lv.1→2 が 1,000 で、そこから1段ごとに約1.3倍（10の位で丸め）に増えます。 到達に必要な累計は Lv.2 = 1,000、Lv.5 = 6,190、Lv.10 = 32,080 です。

🎯 なぜこの機能が必要？

散歩を続けるきっかけを作るためです。歩いた分・口コミを書いた分だけ案内役が育つと、 「もう少し歩こう」「口コミも残そう」という動機になります。

前提条件書では「マスコットのレベルの決め方」が「今後追加予定の要素（未対応）」として残っています。 このマージ群で実績・しきい値・画像がそろい、実際にレベルが変わるようになりました（前提条件書側は未更新です）。

🔄 処理の流れ

Step 1: 実績の取得（ホーム画面を開いたとき）
RouteConditionView の onMounted で mascotStore.loadExperience() を呼び、 GET /api/v1/experience から累計距離・累計時間・投稿件数を受け取ります。 ルート提案画面へ直接来た（再読み込みした）場合は、提案画面でも取り直します。
Step 2: サーバー側（getUserExperience Lambda）
Cognito の sub で利用者を特定し、WalkResult テーブルの累計アイテムを GetItem、 Review テーブルの GSI-UserReview を件数だけ Query して返します。 経験値やレベルはサーバーでは計算しません。生の実績だけを返します。
Step 3: 経験値とレベルの計算（フロント）
ストアの computed が toExperiencePoints → toMascotLevelProgress の順に呼び、 レベル・レベル内の経験値・次までの必要経験値・割合を求めます。各画面はこれを読んでマスコットの姿と経験値バーを描きます。
Step 4: 散歩の終了時にレベルアップを判定（案内画面）
終了確認で「終了する」を押すと、実績を保存した後で mascotStore.refreshAndDetectLevelUp() を呼びます。 取り直す前後のレベルを比べ、上がっていれば経由したレベルの一覧（例: [4, 5]）を pendingLevelUpLevels へ積みます。この間は全画面に「記録中…」を出します。
Step 5: お祝い演出（散歩結果画面）
WalkResultView は pendingLevelUpLevels が空でなければ最初に MascotLevelUpCelebration を出し、 1段ずつタップで進めます。最後の段を閉じると clearPendingLevelUp() で一覧を消し、結果の本体を表示します。

💻 コードの解説

frontend/src/constants/mascotExperience.js

係数とレベル表の唯一の定義元です。

export const MASCOT_LEVEL_REQUIREMENTS = [
  1000, 1300, 1690, 2200, 2860, 3720, 4840, 6290, 8180
];

export const MASCOT_LEVEL_THRESHOLDS = MASCOT_LEVEL_REQUIREMENTS.reduce(
  (thresholds, requirement) => [
    ...thresholds,
    thresholds[thresholds.length - 1] + requirement
  ],
  [0]
);

「各レベルの必要経験値」だけを手で書き、「到達に必要な累計」は足し上げて作ります。 両方を手で書くと、片方だけ直したときにレベルが黙って狂うためです。

frontend/src/utils/mascotLevelProgress.js

export const toExperiencePoints = ({ cumulativeDistanceM, cumulativeMinutes, reviewCount }) => {
  const reviewPoints = toFiniteNumber(reviewCount) * EXPERIENCE_PER_REVIEW;
  const distancePoints =
    (toFiniteNumber(cumulativeDistanceM) / METERS_PER_KM) * EXPERIENCE_PER_KM;
  const minutePoints = toFiniteNumber(cumulativeMinutes) * EXPERIENCE_PER_MINUTE;

  return Math.floor(reviewPoints + distancePoints + minutePoints);
};
  • 入力: 累計距離（メートル）・累計時間（分）・投稿件数
  • 出力: 累計経験値（整数）
  • 切り捨ては3項の合計に対して1回だけ行います。項ごとに丸めると、同じ距離でも分け方で結果が変わるためです
  • 数値でない値（欠けた応答など）は 0 として扱います

toMascotLevelProgress(totalExperiencePoints) はレベルと進捗をまとめて返します。 Lv.10 は次が無いので、experienceToNextLevel を null、割合を 1 にします（0 で割らないため）。 経験値バーはこのとき「MAX」と表示します。

frontend/src/stores/mascotStore.js

名前役割
loadExperience()実績を取得する。失敗しても例外を投げず、hasExperience = false（Lv.1・バーなし）で続ける
hasExperience取得に成功したか。「実績0で取得できた」と「取得できなかった」を区別する
isExperienceLoaded取得を一度でも終えたか（成否を問わない）。ホームはこれが真になるまでマスコットを出さない
mascotLevel画面に出すレベル。取得できていなければ Lv.1
refreshAndDetectLevelUp()取り直してレベルアップを判定し、pendingLevelUpLevels へ積む
clearPendingLevelUp()演出を見せ終えたら一覧を消す
resetExperience()サインアウト時に初期化し、次の利用者に前の人のレベルを出さない
const refreshAndDetectLevelUp = async () => {
  const levelBeforeWalk = isExperienceLoaded.value ? mascotLevel.value : null;

  await loadExperience();

  if (!hasExperience.value || levelBeforeWalk === null) {
    pendingLevelUpLevels.value = [];
    return;
  }
  ...
  for (let level = levelBeforeWalk + 1; level <= levelAfterWalk; level += 1) {
    levels.push(level);
  }
  pendingLevelUpLevels.value = levels;
};

散歩前のレベルが分からない（一度も取得していない）ときは null にして判定しません。 未取得の Lv.1 を基準にすると、取り直しただけで「Lv.1 → Lv.5 にレベルアップ」と誤って祝ってしまうためです。

backend/functions/getUserExperience/

handler → service → repository の3層です（バリデーションする入力が無いため validator はありません）。

export const getUserExperience = async ({ userId }, repository = experienceRepository) => {
  const [walkTotals, reviewCount] = await Promise.all([
    repository.getWalkTotalsByUserId(userId),
    repository.getReviewCountByUserId(userId)
  ]);

  return {
    cumulativeDistanceM: walkTotals?.cumulativeDistanceM ?? 0,
    cumulativeMinutes: walkTotals?.cumulativeMinutes ?? 0,
    reviewCount
  };
};
  • 2つの取得は互いに依存しないので Promise.all で同時に行います
  • まだ散歩を保存していない人には累計アイテムが無いので、0 として返します（エラーにしない）
  • 件数は Select: 'COUNT' で数え、口コミの本文は受け取りません。1回の応答は1MBで切れるため、続きがある限りページを送って合算します
  • テーブル名の環境変数が未設定なら、0 ではなくエラー（DATA_SOURCE_ERROR）にします。「実績0」と「読めなかった」を取り違えると、レベルが下がったように見えるためです

frontend/src/components/feature/mascot/MascotLevelUpCelebration.vue

  • 入力: levels（見せるレベルの昇順の配列）
  • 出力: 最後の段を閉じたとき close を emit
  • タップ・Enter・Space で次の段へ進み、Esc でいつでも閉じられます。時間では進みません
  • 画像は1枚絵なので、旧→新は「フェードアウト → 光 → フェードイン」で切り替えます
  • 開いたときにフォーカスを演出へ移し、閉じたら元の要素へ戻します（キーボード・読み上げの利用者が迷わないため）

⚠️ 注意ポイント

レベルアップの判定は案内画面の終了処理でだけ行う
ホームや提案画面の loadExperience() でも実績は取り直しますが、そこではレベルアップを判定しません。 判定を refreshAndDetectLevelUp() に閉じ込めることで、画面を行き来しただけで演出が出る誤発火を防いでいます。 チュートリアル中は経験値を動かさないため、判定も演出も行いません。
係数・レベル表を変えるときはフロントだけ直す
API は生の実績を返すだけなので、係数（1km=100 など）やレベル表を変えてもバックエンドとAPIはそのままで済みます。 ただし変えると、既存の利用者のレベルが一斉に変わります。
API のパスが単数（/experience）
規約は「パスは複数形」ですが、experiences だと「体験」に読めるため意図的に単数にしています（michishiru-stack.ts のコメントに記載）。
画像の容量
0b675e9 で Lv.2〜10 の画像が 1〜3.7MB に増えました（Lv.1 は約42KB のまま）。成果物が増えた結果、S3 へ配置する裏方の Lambda が 既定の 128MB でメモリ不足になり、デプロイがタイムアウトまで止まる問題が起きたため、cabcdf5 で memoryLimit: 512 にしています。 また、使われていない画像フォルダ（assets/images/mascot _bk/ / assets/images/mascot20261021/）がリポジトリに残っています。

✅ 動作確認方法

  1. ローカルで実績を読むには AWS の認証情報と環境変数 WALK_RESULT_TABLE_NAME / REVIEW_TABLE_NAME が必要です。未設定だと API は 503 を返し、画面は Lv.1・経験値バーなしで続きます（その動きも確認対象）
  2. npm run dev で起動し、ホーム画面でマスコットのレベル名と経験値バーが出ることを確かめる
  3. 散歩を最後まで行い（短い距離で可）、「終了する」の後に「記録中…」が出て、レベルが上がったときだけ演出が出ることを確かめる
  4. 演出をタップで進め、閉じた後に結果画面が出ること、結果画面から戻って再び来ても演出が再演されないことを確かめる
  5. テスト: frontend で npm test（src/constants/__tests__/mascotExperience.test.js / src/utils/__tests__/mascotLevelProgress.test.js）、 backend で npm test（functions/getUserExperience/__tests__/）、iac で npm test
