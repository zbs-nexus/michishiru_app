🧩 先に知っておきたいこと

Vue のコンポーネントと props
コンポーネントは画面の部品で、1ファイル（.vue）が1部品です。部品の見た目や文言を外から変えたいときは「props（プロップス）」という入れ口を用意し、使う側から値を渡します。この機能では「マスコットのレベル」「表示サイズ」「吹き出しの並べ方」などを props で渡しています。
CSS カスタムプロパティ（CSS変数）と :root
CSS では --primary-color: #45356B; のように自分で名前を付けた値を定義し、color: var(--primary-color) で呼び出せます。:root はページ全体を指す書き方なので、ここに定義しておけばどのコンポーネントからも同じ名前で参照できます。この機能の土台はこの仕組みです。
スロット（slot）
props が「値」を渡す仕組みなのに対し、スロットは「HTMLの中身そのもの」を渡す仕組みです。<slot /> と書いた場所に、使う側がタグの内側に書いた内容がそのまま入ります。吹き出しの中身は画面ごとに見出し＋本文など形が違うため、スロットで受け取っています。
画面読み上げ（支援技術）と代替テキスト
目が見えにくい人はスクリーンリーダーという読み上げソフトで画面を使います。画像には alt 属性で説明文を書き、文言が差し替わる場所には role="status" や aria-live を付けると「変わったこと」が読み上げられます。逆に alt="" と aria-hidden="true" を付けると、その要素は読み上げの対象から外れます。
Webフォントの「自前配信」と「外部CDN」
Webフォント（ブラウザがダウンロードして使う書体）は、他社のサーバー（CDN）から読み込む方法と、自分のサーバーに置いて配る方法（自前配信）があります。どちらを選ぶかで、通信先・読み込みの速さ・プライバシーが変わります。この機能では自前配信を選んでいて、その理由は後述します。

📖 この機能について

この変更は、アプリの見た目全体を「羊皮紙と古地図」のファンタジー調に揃え、案内役のマスコット（フクロウ）を各画面に登場させるものです。機能としての振る舞い（ルートを作る、案内する）は変えていません。変わったのは次の4点です。

  • 配色と書体を global.css の :root に集約し、羊皮紙の地色・金の縁取り・紫のインクの3点で全画面を揃えた
  • マスコットの部品（MascotAvatar / MascotSpeechBubble）を新規に作り、各画面のコメントを吹き出しで話させた
  • 見出しの書体を「解星特ミン」に変え、外部CDNではなく自前で配信するようにした（10/14 にアプリ全体が DotGothic16 へ変更。自前配信の方針は同じ）
  • デザインを確認するための開発専用画面（/design-preview）を追加した

マスコットは Lv.1〜Lv.10 まで姿が変わる想定で、名前の一覧と画像の対応表だけ先に用意してあります。現時点で画像があるのは Lv.1「ミチのタマゴ」だけです。

🎯 なぜこの機能が必要？

これまでの画面は、紺色（#2D3E50）と白を基調にした一般的な業務アプリ寄りの見た目でした。配色の変数は global.css にいくつかありましたが、書体の指定は body に直接書かれており、各コンポーネントにも #1f5fa8 #ddd のような色が直接書かれていました。この状態には2つの困りごとがあります。

  • 散歩アプリらしい世界観がない。 「知らない道を歩く楽しさ」を伝える見た目になっていない
  • 色を変えたいとき、全ファイルを探して直すことになる。 直し漏れが出て画面ごとに色がずれる

そこで、色と書体の定義を1か所に集めたうえで世界観を作り直し、同時に「アプリが話しかけてくる」案内役としてマスコットを置きました。マスコットは単なる飾りではなく、これまで画面の地の文として置かれていたコメント（「ルートを作成中...」「お疲れさまでした」など）を話す役です。

この方針は前提条件書の「確定した要素」に記録されています（画面デザインの方向性 / マスコットの表示方法 / 見出しの書体 / Webフォントの配信方法、いずれも 2026/10/07 確定）。対応する画面は US-1（ホーム）、US-2（ルート作成中）、US-3（ルート提案）、US-6（案内）、US-8（散歩結果）です。受け入れ条件そのものは変えていません。

🔄 処理の流れ

この変更は「実行時にこう動く」というより「どの層で何を決めるか」という組み立ての話です。下から順に積み上がっています。

Step 1: 配色と書体を global.css の :root に集約する
色（羊皮紙・金・紫のインクなど）と書体（見出し用・本文用）を変数として定義します。ここが土台で、以降のすべての画面・部品はこの変数を参照します。
Step 2: マスコットのレベル定義表を作る（constants/mascotLevels.js）
Lv.1〜Lv.10 の「レベル・名前・画像」の対応表を1か所に置きます。画像が未用意のレベルは null にしておきます。
Step 3: 姿だけを表示する部品を作る（MascotAvatar.vue）
レベルを受け取り、定義表から画像と名前を引いて表示します。何を話すかは持ちません。
Step 4: 吹き出しと組み合わせる部品を作る（MascotSpeechBubble.vue）
内部で MascotAvatar を呼び、その隣（または上）に吹き出しを置きます。話す内容は props の message かスロットで受け取ります。
Step 5: 各画面に1体ずつ組み込む
ホーム・ルート作成中・ルート提案・案内・散歩結果の5か所に、それぞれ1体だけ置きます。画面がすでに持っていたコメントを吹き出しの中へ移します。
Step 6: 見出しの書体を自前配信で読み込む（main.js）
npm パッケージ @fontsource/kaisei-tokumin（5.3.0）を入れ、main.js から動的 import で読み込みます。これでフォントのファイルも自分のサーバー（CloudFront + S3）から配られます。
Step 7: デザイン確認用の画面を足す（DesignPreviewView.vue）
ログイン済みの状態と作成済みのルートをストアへ入れてから各画面へ飛ばす開発専用の画面です。Cognito もルート作成APIも呼ばずに本物の画面を確認できます。

💻 コードの解説

frontend/src/assets/styles/global.css（配色と書体の定義）

全画面の色と書体をここで決めます。各コンポーネントは色コードや書体名を書かず、この変数名だけを使います。 

:root {
  /* 紫のインク。見出し・主要ボタン・つまみに使う */
  --primary-color: #45356B;
  --primary-light: #5F4C91;
  /* 森の緑。開始地点マーカーと案内バナーの帯に使う */
  --accent-green: #3F7A5C;
  /* 金。飾りと縁取り専用。明るい面の文字色には使わない（コントラストが足りない） */
  --accent-gold: #B8862B;
  --border-gold: #DCC48A;
  /* ルートを示す青。mapDefaults.js の ROUTE_LINE_COLOR と同値にする */
  --route-blue: #1A73E8;
  /* 羊皮紙。画面の地の色 */
  --bg-light: #FBF4E4;
  --bg-deep: #F1E3C8;
  --bg-map: #E4EDDC;
  /* カードや吹き出しの面。紙より少し明るいクリーム */
  --surface: #FFFCF4;
  --surface-alert: #FDF0EE;
  --text-dark: #3A2E20;
  --text-gray: #6B5B46;
  --danger: #B3372B;
  ...
  --font-display: 'Kaisei Tokumin', 'Hiragino Mincho ProN', 'Yu Mincho', 'YuMincho', 'Noto Serif JP', 'Georgia', serif;
  --font-body: -apple-system, BlinkMacSystemFont, 'Segoe UI', 'Hiragino Sans', sans-serif;
}

変更前との違い： 以前は --primary-color: #2D3E50（紺）などの色変数が10個弱あるだけで、書体は body に直接書かれていました。今回は書体も --font-display / --font-body として変数にしたため、書体を変えたいときに直すのはこの1行と main.js の読み込み行だけになります。

--font-display に書体名が6つ並んでいるのは「候補リスト」です。先頭の Kaisei Tokumin が読み込めなかった場合、ブラウザは順に次を試し、最後は端末の明朝体で表示します。見た目は多少変わりますが、文字が出ないことはありません。

frontend/src/constants/mascotLevels.js（レベルの定義表）

レベルと名前と画像の対応表、およびレベルから定義を引く関数を持ちます。画面側はこのファイルだけを見れば済みます。 

export const MASCOT_LEVELS = [
  { level: 1, mascotName: 'ミチのタマゴ', mascotImage: mascotLv01Image },
  { level: 2, mascotName: 'よちよちヒナ', mascotImage: null },
  { level: 3, mascotName: 'てくてくフクロウ', mascotImage: null },
  ...
  { level: 10, mascotName: '極・ミチシル', mascotImage: null }
];

export const getMascotLevel = (level = DEFAULT_MASCOT_LEVEL) => {
  const requested = MASCOT_LEVELS.find(
    (definition) => definition.level === level
  );

  if (requested?.mascotImage) {
    return requested;
  }

  const requestedLevel = requested?.level ?? DEFAULT_MASCOT_LEVEL;
  const substitute = availableMascotLevels
    .filter((definition) => definition.level <= requestedLevel)
    .at(-1);

  return substitute ?? availableMascotLevels[0];
};

入力： レベル（数値）。省略すると DEFAULT_MASCOT_LEVEL（= 1）。
出力： { level, mascotName, mascotImage } の形のオブジェクト。必ず画像が入ったものを返します。

ポイントは「画像が未用意のレベルを渡されても壊れない」ことです。例えば Lv.5 を渡しても画像がまだ無いので、用意済みで最も高いレベル（今は Lv.1）の姿を返します。これにより、画面側に「画像が無かったらどうするか」の分岐を書かずに済みます。 新しい姿が描けたら、画像を追加して null を差し替えるだけで全画面に反映されます。

frontend/src/components/feature/mascot/MascotAvatar.vue（姿の表示）

レベルから画像と名前を引いて表示するだけの部品です。話す内容は持ちません。 

<img
  class="mascot-image"
  :src="mascot.mascotImage"
  :alt="isDecorative ? '' : mascotLabel"
  :aria-hidden="isDecorative ? 'true' : undefined"
>

props は4つです。

props 既定値 意味
level DEFAULT_MASCOT_LEVEL（1） 表示するマスコットのレベル
size 'medium' 表示サイズ。small（44px）/ medium（76px）/ large（128px）の3段階
hasLevelLabel false 真のとき Lv.1 ミチのタマゴ という札を画像の下に添える
isDecorative false 真のとき代替テキストを空にし、読み上げソフトから隠す

isDecorative がなぜ必要か。 role="status" を付けた箱の中身が変わると、読み上げソフトはその箱の中身を読み直します。案内画面の帯（次の目的地と距離）はまさにこれで、距離が10m動くたびに読み直されます。このときマスコットの画像の説明（「Lv.1 ミチのタマゴ」）まで一緒に読まれると、肝心の目的地名の前に毎回同じ言葉が挟まって邪魔になります。そこで「この画像は飾りで、意味は持たない」と伝えるのが isDecorative です。

frontend/src/components/feature/mascot/MascotSpeechBubble.vue（吹き出し）

マスコットの姿と吹き出しを組み合わせる部品です。1画面に1体だけ置きます。 

<div
  class="mascot-speech"
  :class="[`is-${placement}`, { 'is-alert': isAlert }]"
>
  <MascotAvatar
    :level="level"
    :size="size"
    :has-level-label="hasLevelLabel"
  />

  <!-- 文言が入れ替わるため読み上げの対象にする。注意のときだけ割り込ませる -->
  <div
    class="speech-bubble"
    :role="isAlert ? 'alert' : 'status'"
    :aria-live="isAlert ? 'assertive' : 'polite'"
  >
    <slot>{{ message }}</slot>
  </div>
</div>

<slot>{{ message }}</slot> の書き方により、短い一文なら message props で渡し、見出し＋本文のような複数行ならタグの内側に書くという2通りの使い方ができます。スロットに何も入れなければ message が表示されます。

追加された props は2つです。

props 値 意味
placement side（既定） / stacked マスコットと吹き出しの並べ方。side は横並び（左にマスコット）、stacked は吹き出しを上・マスコットを下に置く
variant normal（既定） / alert 吹き出しの種類。alert は縁取りと文字色を赤に変え、読み上げも割り込みで伝える

stacked は CSS の flex-direction: column-reverse で実現しています。HTMLの並び順はマスコットが先のままで、見た目だけ逆にしています。読み上げの順序は HTML の順序に従うため、見た目を変えても読み上げ順は変わりません。

variant の値が alert のときは role="alert" と aria-live="assertive" になります。polite が「今読んでいる内容が終わってから伝える」、assertive が「割り込んですぐ伝える」です。異常を知らせるときだけ割り込ませる、という使い分けです。

なお variant という props 名は BaseToast でも使われていますが、取る値は別（トーストは error / omakase）です。どちらも「その部品の見た目の種類」を指す語として使っています。

frontend/src/views/RouteConditionView.vue（ホーム画面での使い方）

画面が持っている3つの状態（読み込み中・条件を出せない・入力待ち）を、そのままマスコットの文言に変換しています。 

const mascotMessage = computed(() => {
  if (isLoadingOptions.value) {
    return '地図をひろげているよ。少し待っていてね';
  }

  if (!hasConditionOptions.value) {
    return optionsErrorMessage.value ?? '条件をよみこめなかったみたい。もう一度ためしてね';
  }

  return 'どんなお散歩にする？ ジャンルと距離をえらんで、ぼくに教えて！';
});

/** 吹き出しの種類。条件を出せないときだけ注意として見せる */
const mascotMessageVariant = computed(() =>
  !isLoadingOptions.value && !hasConditionOptions.value ? 'alert' : 'normal'
);

computed（算出プロパティ）は「元になる値が変わったら自動で計算し直される値」です。読み込みが終われば isLoadingOptions が false になり、文言も自動で入力待ちのものに切り替わります。テンプレート側はこう書かれています。 

<MascotSpeechBubble
  class="home-mascot"
  :message="mascotMessage"
  :variant="mascotMessageVariant"
  placement="side"
  size="medium"
/>

失敗の理由を吹き出しで伝えるようにしたため、画面上に別のエラー文を置く必要がなくなりました。エラー時に残るのは「再読み込み」ボタンだけです。

frontend/src/components/feature/route/RouteNextSpotBanner.vue（案内画面での使い方）

ここだけは吹き出しを使わず、MascotAvatar を直接使っています。帯そのものが案内役の言葉として見えればよく、吹き出しの枠を重ねると狭くなるためです。 

<!--
  読み上げ範囲の中にあるため装飾として置く。
  距離が変わるたびにマスコットの説明が読み直されるのを防ぐ。
-->
<MascotAvatar
  size="small"
  is-decorative
/>

is-decorative と書くと isDecorative に true が渡ります（値を省略した属性は true 扱い）。宣言は camelCase、HTMLに書くときは kebab-case、というVueの決まりに従った書き方です。

frontend/src/main.js（フォントの自前配信）

見出しの書体を npm パッケージから読み込みます。1行ですが、コメントに判断の理由が書かれています。 

/*
 * 見出し用の書体（解星特ミン）。外部CDNへ取りに行かせないため自前で配信する。
 * 使っているのは太字だけなので、ウェイトは700のみ読み込む。
 *
 * 日本語は文字数が多く、文字の範囲ごとに分割された @font-face の定義だけで
 * 90KB（gzip後）を超える。最初の描画を待たせないよう、動的importで
 * 本体のCSSから切り離して後から読み込む。
 * 読み込めるまでの間は --font-display の次の候補（端末の明朝）で表示される
 * （font-display: swap）。
 */
import('@fontsource/kaisei-tokumin/700.css');

※ 10/07 時点のコードです。現在（4e24e22 以降）は import('@fontsource/dotgothic16/400.css'); の1行で、見出しも本文も DotGothic16 です。下の「🆕」の節を参照してください。

ファイルの先頭に並ぶ import ... from ... は「このファイルを動かす前に必ず読み込む」宣言ですが、import('...') という関数の形（動的 import）は「別の荷物として後から取りに行く」書き方です。こうすると書体の定義が本体のJS/CSSから切り離され、最初の表示を待たせません。

なぜ外部CDNを使わないのか。 前提条件書に理由が3つ挙げられています。

  1. キャッシュの利点が消えた。 以前は「他のサイトで同じCDNのフォントを読み込んでいれば、ブラウザの保存済みデータが再利用されて速い」という利点がありました。しかし2020年以降、ブラウザはキャッシュをサイトごとに分けて保存するようになり、この利点はなくなりました
  2. 訪問者のIPアドレスが第三者に渡る。 CDNからフォントを取りに行くと、利用者の端末が直接その会社のサーバーへ通信します
  3. 同一オリジンで閉じた設計と噛み合わない。 ミチシルはフロントもAPIも同じ CloudFront のドメインから配る設計（だからCORS設定が不要）です。フォントだけ外部に依存させる理由がありません

書体「解星特ミン（Kaisei Tokumin）」は SIL Open Font License で公開されているため、自分のサーバーに置いて配ることができます。

frontend/src/router/index.js（開発専用画面の登録）

デザイン確認用の画面は、開発サーバーで動かしているときだけ登録します。 

/**
 * デザイン確認用の画面。開発サーバーでのみ登録する。
 * 本番ビルドでは import.meta.env.DEV が false になり、
 * この画面とDesignPreviewViewのコードは成果物に含まれない。
 */
if (import.meta.env.DEV) {
  routes.unshift({
    path: '/design-preview',
    name: 'design-preview',
    component: () => import('@/views/DesignPreviewView.vue'),
    meta: { isPreview: true }
  });
}

import.meta.env.DEV は、ビルドツール（Vite）が「開発中かどうか」を入れてくれる値です。本番ビルドではこれが false になり、if の中が通らないと分かるため、プレビュー画面のコードそのものが成果物（dist）から取り除かれます。

さらにルーターの入口（beforeEach）でも、meta.isPreview を持つこの画面だけはログイン判定より先に通しています。ログイン済みの状態を作るのがこの画面の役目なので、判定を先に通すとログイン画面へ飛ばされてしまうためです。この meta を持つ画面は本番ビルドでは登録されないため、本番では効きません。

⚠️ 注意ポイント

0. ドット絵の枠と角丸は併用できない（10/21 追加）

border-image の枠は四角いのに背景だけ角が丸まるため、ドット絵の枠を使う要素では border-radius を書かないでください。 また枠の太さ（--pixel-frame-width）を変えると要素が外へ広がるので、ジャンルの4列やボタンの高さが崩れていないか確かめてください。

1. マスコットは1画面に1体だけ

かわいいので増やしたくなりますが、1画面に1体という決まりです。2体以上置くと「どれが今話しているのか」が分からなくなり、読み上げの対象（role="status"）も複数できて読み上げが重なります。現在の配置は次の5か所です。

画面 置いている場所 使っている部品
ホーム（US-1） RouteConditionView.vue MascotSpeechBubble（side / medium）
ルート作成中（US-2） RouteLoadingOverlay.vue MascotSpeechBubble（stacked / large）
ルート提案（US-3） RouteInfoCard.vue MascotSpeechBubble（side / medium）
案内（US-6） RouteNextSpotBanner.vue MascotAvatar（small / 装飾）
散歩結果（US-8） WalkResultView.vue MascotSpeechBubble（stacked / large / レベル札あり）

ログイン・ユーザー登録・パスワード再設定の3画面にはマスコットを置いていません。これらの画面は配色と書体の変更（ロゴ見出しの書体が変わり、ロゴ下の説明文を1行削除）だけを受けています。

2. 色と書体をコンポーネントに直書きしない

新しく画面や部品を作るとき、color: #45356B のように色コードを書いてはいけません。color: var(--primary-color) と書きます。書体も font-family: var(--font-display) です。直書きすると、配色を見直したときにその箇所だけ取り残され、画面ごとに色が違う状態になります。

例外は rgba() で作る影や光のような、半透明の重ね色です（マスコット背後の光など）。これらは変数にすると種類が増えすぎるため、その部品の <style scoped> の中に書いています。

3. 読み上げ範囲の中に画像を置くときは装飾にする

role="status" や role="alert" を付けた箱の中にマスコットを置く場合は、必ず is-decorative を付けます。付け忘れると、文言が変わるたびに「Lv.1 ミチのタマゴ」が読み上げられ、肝心の内容が頭に入らなくなります。

逆に、吹き出しの外（読み上げ範囲の外）に単体で置く場合は付けません。その場合はマスコットの説明が1回だけ読まれるのが正しい動きです。

4. レベルは枠組みだけで、まだ Lv.1 しか見えない

Lv.1〜Lv.10 の名前と、レベルから定義を引く関数は用意済みですが、Lv.2 以降の画像はまだありません。 また「どの実績でレベルが上がるか」（累積距離・散歩回数などのしきい値）も決まっていません。

そのため現在は全画面が DEFAULT_MASCOT_LEVEL（Lv.1）を表示します。画像が増えたら mascotLevels.js の mascotImage: null を差し替えるだけでよく、呼び出し側のコードは変えません。しきい値の決定は前提条件書の「今後追加予定の要素」に残っています。

5. プレビュー画面を本番に出さない

DesignPreviewView は、ログイン済みの状態とAPI認可用のダミートークンを自分で作る画面です。本番に出れば誰でもログインを迂回できてしまいます。登録箇所の import.meta.env.DEV の条件を外さないでください。

6. 用語は辞書に揃える

キャラクターを指す語は mascot に統一します（character / chara は使いません）。吹き出しは speechBubble で、balloon / tooltip は使いません（tooltip は補助説明という別の概念です）。立ち絵は MascotAvatar と接頭辞を付けます。avatar 単独だと利用者のアイコンと混同するためです。

✅ 動作確認方法

  1. フロントとAPIを同時に起動する（リポジトリのルートで実行） 
    npm run dev
  2. デザイン確認用の画面を開く
    ブラウザで http://localhost:5173/design-preview を開きます。画面上部に赤い「開発時のみ / デザイン確認用」の札が出ます。
  3. 5つの画面のマスコットを順に確認する
    「ホーム画面」「ルート作成中画面」「ルート提案画面」「ルート案内画面」「案内終了画面」のボタンから移動します。案内画面は位置情報の許可を求められます。各画面でマスコットが1体だけ表示され、吹き出しにその画面のコメントが入っていればOKです。元の画面へ戻るときはブラウザの戻るか、/design-preview を開き直します。
  4. 吹き出しの注意表示を確認する
    ホーム画面で検索条件マスタの取得に失敗させると（APIサーバーを止めるなど）、吹き出しの縁取りと文字が赤に変わり、「再読み込み」ボタンだけが残ります。
  5. 見出しの書体を確認する
    ロゴの「ミチシル」や見出しが明朝体の太字になっていればフォントが効いています。ブラウザの開発者ツールのネットワークタブで、フォントの取得先が localhost（本番では自分のドメイン）になっていること、外部のCDNへ通信していないことも確認できます。
  6. チェックとビルドを通す（frontend/ で実行） 
    npm run lint
npm run build
npm test

    この変更はマスコットの部品に対するテストを追加していないため、npm test は既存のテストのみが走ります。見た目の確認は上記の手順で目視で行います。
