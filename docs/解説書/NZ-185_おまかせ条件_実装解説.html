📖 この機能について

ホーム画面の「ジャンル」と「距離」の見出しの横に ？ ボタンが付きました。押すと「おまかせ」になり、ルートを作るときにアプリがジャンルや距離を自動で選びます。選ばれた内容は、ルート提案画面の上部に「おまかせ」ラベル付きのお知らせ（トースト）で表示されます。

トースト: 画面の端に数秒だけ出て自動で消える小さな通知のことです。

🎯 なぜこの機能が必要？

  • 「どこでもいいから歩きたい」という人は、ジャンルや距離を選ぶこと自体が面倒です。
  • 毎回同じジャンルを選びがちな人に、普段選ばない散歩を提案できます。
  • おまかせ中に「再作成」を押すと毎回選び直すので、押すたびに違う散歩が出てきます。

🔄 処理の流れ

[ホーム画面]  ？ボタンを押す
      │  routeStore.isGenreRandom / isDistanceRandom が true に
      ▼
[ルート作成ボタン]
      │  POST /api/v1/routes  { isGenreRandom: true, isDistanceRandom: true, ... }
      ▼
[Lambda createRoute]
      │  validator … おまかせの項目は未指定でもOK
      │  service   … 検索条件マスタを全件読み、ランダムに選ぶ
      │              → いつもどおりスポット検索・AI・経路計算
      │  handler   … 選んだ値を selected_genres / selected_distance_km で返す
      ▼
[ルート提案画面]  「おまかせ」トーストで選ばれた内容を表示
Step 1: おまかせを切り替える（フロント）
RouteConditionForm.vue の ？ ボタンが toggleGenreRandom / toggleDistanceRandom を emit し、routeStore が状態を切り替えます。おまかせ中はジャンルのボタン群や距離スライダーを隠し、「おまかせでジャンルを選択します」と表示します。ジャンルをおまかせにすると、手動で選んでいたジャンルは消えます。
Step 2: リクエストを送る（フロント）
useRouteCreation.js が、おまかせの項目は値を undefined（送らない）にし、代わりに isGenreRandom / isDistanceRandom を送ります。
Step 3: 入力チェック（バックエンド validator）
おまかせの項目は「未指定でもエラーにしない」ようにしました。おまかせでない項目は従来どおりチェックします。
Step 4: ランダムに選ぶ（バックエンド service）
conditionRepository.listConditions() で検索条件マスタを読み、pickRandomGenres（ジャンルを1件〜全件）と pickRandomDistanceKm（1km 単位の距離）で選びます。そのあとはこれまでと同じルート作成処理に、選んだ値を渡します。
Step 5: 選んだ値を知らせる
レスポンスに選んだ値を含め、RouteSuggestionView.vue が「ジャンル: 自然・歴史 / 距離: 3km で選びました」のようなトーストを出します。再作成したときも新しい値で出し直します。

💻 コードの解説

backend/functions/createRoute/service.js — ジャンルを選ぶ

const pickRandomGenres = (conditionItems) => {
  const genreItems = conditionItems.filter(
    (item) => item.pk === GENRE_CONDITION_PK && item.isActive && item.genreId
  );
  // ...0件ならエラー
  const selectCount = Math.floor(Math.random() * genreItems.length) + 1;

  return shuffleItems(genreItems)
    .slice(0, selectCount)
    .map((item) => ({ genreId: item.genreId, genreName: item.genreName ?? item.genreId }));
};
  • 入力: 検索条件マスタの全項目。出力: { genreId, genreName } の配列。
  • マスタのうち pk が GENRE#ALL で、有効（isActive）なものだけが候補です。
  • 選ぶ件数も1〜全件の中でランダムです。複数選ばれると、各ジャンルのカテゴリをまとめてスポット検索します。
  • shuffleItems は Fisher-Yates 法（配列を偏りなく並べ替える定番の方法）です。以前 limitSearchCategories の中にあった処理を関数に切り出して使い回しています。

backend/functions/createRoute/service.js — 距離を選ぶ

const minKm = Math.ceil(Math.max(Math.min(...distancesKm), TARGET_DISTANCE_RANGE_KM.min));
const maxKm = Math.floor(Math.min(Math.max(...distancesKm), TARGET_DISTANCE_RANGE_KM.max));
// ...
return minKm + Math.floor(Math.random() * (maxKm - minKm + 1));
  • マスタの距離項目（pk が DISTANCE#ALL）の最小〜最大の間から、整数の km を選びます。
  • API が受け付ける範囲（TARGET_DISTANCE_RANGE_KM）からはみ出さないように、両端を切り詰めています。

resolveSpotCategoryIdsForGenres — 複数ジャンルのカテゴリをまとめる

ジャンルが1つなら従来どおり。複数のときは Promise.allSettled（一部が失敗しても全部の結果を待つ仕組み）で並列に引き、引けなかったジャンルは警告ログを出して飛ばします。1件も引けなければエラーです。

backend/functions/createRoute/repositories/conditionRepository.js（新規）

検索条件マスタを Scan（テーブルの全件読み）で取得するだけの Repository です。どれを選ぶかの判断は Service 層が行い、レイヤーの責務を分けています。スロットリング（アクセス集中による一時的な拒否）のときは待ち時間を倍にしながら最大3回やり直します。

⚠️ 注意ポイント

選んだ値は入力条件に書き戻さない
おまかせで選ばれたジャンル・距離は currentRoute（ルート側）が持ち、ストアの genre / distanceKm は変えません。書き戻すと、再作成のときに「おまかせ」ではなく前回の値で作ってしまうためです。
レスポンスのキーが snake_case
selected_genres / selected_distance_km は、既存レスポンス（route_title など）の外部仕様に合わせて snake_case です。規約上は camelCase が正しく、handler.js に TODO があります。直すときはフロントの utils/routeResponse.js と同時に変えてください。
検索条件マスタに距離・ジャンルが登録されている必要がある
マスタに有効なジャンル（または距離）が1件もないと、おまかせは「マスタに登録されていません」というエラーになります。ローカルで試すときはマスタのデータを確認してください。
CSS の状態クラス名
RouteConditionForm.vue の選択状態は selected クラスで表しています。規約（component-design.md）では is-selected の形なので、次に触るときに揃えるとよいです。

✅ 動作確認方法

  1. リポジトリのルートで npm run dev を実行し、フロントとローカルAPIを同時に起動します。
  2. ホーム画面で「ジャンル」横の ？ を押し、ジャンルのボタンが「おまかせでジャンルを選択します」に変わることを確認します。距離も同様です。
  3. ルート作成ボタンを押し、提案画面に「おまかせ」ラベル付きのトーストが出て、選ばれたジャンル・距離が書かれていることを確認します。
  4. 「再作成」を押し、トーストの内容が変わる（選び直される）ことを確認します。
  5. もう一度 ？ を押しておまかせを解除すると、通常の選択に戻ることを確認します。
  6. 自動テスト: backend/ で npm test。service.test.js / validator.test.js におまかせのテストが追加されています。
  7. フロントのチェック: frontend/ で npm run lint と npm run build（フロントの自動テストは未導入です）。
