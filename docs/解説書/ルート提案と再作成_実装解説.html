ルート提案と再作成 - 実装解説

🗓 対象期間: 2026-09-16 〜 2026-10-14
📅 マージ日: 2026-09-16（3件）, 2026-10-14（1件）
🌿 対象ブランチ: feature/NZ-6, feature/NZ-147, feature/NZ-278
🔖 対象マージ: ec68ced（ルート作成処理の再呼び出し: 再作成でロード表示を正しく解除）, 4c0f3c5（再作成失敗時のエラーをトーストで表示）, 09f2248（詳細画面の削除: 決定で直接案内へ）, a0b759b（提案画面にホームへ戻るボタン）
※ 提案画面のデザイン（一画面に収める 0d851b4、マスコットのレベル表示 e8cd294）は マスコットとファンタジー調デザイン と マスコットのレベルアップ、 おまかせの通知は おまかせ条件、チュートリアル中の動きは チュートリアル で扱います。

🧩 先に知っておきたいこと

routeStore（検索条件と作成済みルートの置き場）
ホームで選んだジャンル・距離・おまかせの状態と、作成したルート（currentRoute）は Pinia の routeStore に入っています。 画面を移っても残るので、提案画面からの再作成でも同じ条件をそのまま使えます。再読み込みすると消えます。
useRouteCreation（ルート作成の composable）
現在地を取り、ルート作成API（POST /api/v1/routes）を呼んで結果を routeStore に入れる処理です。 ホーム画面と提案画面の両方がこれを使います。API の中身は ルート作成API を参照してください。
ルートガード
Vue Router の beforeEach で、画面を開く前に条件を確かめる仕組みです。提案・案内・結果の画面は requiresRoute を持ち、 作成済みのルートが無いとホームへ戻されます。

📖 この機能について

ルート提案画面（/suggestion、RouteSuggestionView.vue）の3つの操作を整えた一連の変更です。

ボタン動き関連する US
決定そのまま案内画面（/navigation）へ進む。以前あった詳細画面は挟まないUS-4
再作成同じ条件でルートを作り直す。作成中はロード画面を出し、失敗したらトーストで知らせて直前のルートを表示し続けるUS-5
ホームに戻る提案を採用せずホームへ戻る。条件はストアに残るので、変えて作り直せるUS-1

画面下部には距離（km）も表示しています（US-3「モーダルに移動距離を表示すること」）。

🎯 なぜこの機能が必要？

  • 再作成でロード画面が消えない問題（ec68ced）: 以前のロード表示は「画面遷移で破棄されるまで出し続ける」作りでした。ホームから作るときは提案画面へ移るので消えますが、提案画面で再作成すると同じ画面に留まるため、ロード画面が残り続けていました。
  • 失敗が伝わらない問題（ec68ced / 4c0f3c5）: 失敗してもロード画面のまま止まっていたため、トーストで理由を出して操作を続けられるようにしました。
  • 決定から案内までの手数（09f2248）: 前提条件書の画面遷移では「決定 → 案内画面」ですが、間に詳細画面がありました。遷移図に合わせて削除しました。
  • 戻る手段（a0b759b）: 提案が気に入らず条件を変えたいとき、ブラウザの戻る以外に手段がありませんでした。

🔄 処理の流れ

Step 1: ホームで作成 → 提案画面へ
RouteConditionView が createRoute() を呼び、成功したら route-suggestion へ進みます。失敗したらトーストを出してホームに留まります。
Step 2: 提案画面を表示
地図のプレビュー（RouteMapPreview）、ルート名・説明・所要時間のカード（RouteInfoCard）、下部に距離と3つのボタンを出します。 おまかせで選ばれた条件があれば、表示したときにトーストで知らせます。
Step 3: 再作成
handleRegenerate が前回のトーストを消してから createRoute() を呼びます。作成中（isCreating）はロード画面（RouteLoadingOverlay）に切り替わり、 終われば成否にかかわらず解除されます。成功すると routeStore.currentRoute が新しいルートに替わり、画面が描き直されます。
Step 4: 決定 / ホームに戻る
決定は route-navigation へ、ホームに戻るは route-condition へ、名前で遷移します。

💻 コードの解説

frontend/src/composables/useRouteCreation.js

const createRoute = async () => {
  isCreating.value = true;
  errorMessage.value = null;
  const startedAt = Date.now();

  try {
    const location = await fetchCurrentLocation();
    const route = await requestRouteCreation({ ... });
    routeStore.setCurrentRoute(route);
    return true;
  } catch (error) {
    errorMessage.value = error.message;
    return false;
  } finally {
    const elapsedMs = Date.now() - startedAt;
    if (elapsedMs < MIN_LOADING_DURATION_MS) {
      await wait(MIN_LOADING_DURATION_MS - elapsedMs);
    }
    isCreating.value = false;
  }
};
  • 出力: 成功なら true、失敗なら false（理由は errorMessage）
  • finally で必ず isCreating を戻します。これが ec68ced の修正の中心です
  • 応答が速すぎるとロード画面が一瞬だけ出てちらつくので、最短表示時間（MIN_LOADING_DURATION_MS）までは待ちます
  • 条件は毎回ストアから読むので、初回作成と再作成で同じ値になります。おまかせの項目は送らず、毎回サーバーが選び直します

frontend/src/views/RouteSuggestionView.vue

const handleRegenerate = async () => {
  // 前回の失敗メッセージが残ったままロード表示へ入らないように消す
  hideMessage();

  const isSucceeded = await createRoute();

  if (!isSucceeded) {
    showMessage(creationErrorMessage.value ?? 'ルートの再作成に失敗しました');
    return;
  }

  // 再作成ではおまかせで選び直されるため、新しい値を知らせる
  showRandomSelectionMessage();
};

テンプレートは isCreating が真ならロード画面、そうでなく currentRoute があれば提案の本体を出します（v-if / v-else-if）。 失敗しても currentRoute は前のままなので、直前の提案が表示され続けます。

⚠️ 注意ポイント

「ルート提案モーダル」は画面として実装されている
前提条件書の US-3 は「地図画面 + ルート提案モーダル」ですが、実装は URL を持つ画面（/suggestion）です。 受け入れ条件（地図への描画・距離・再作成・決定）は満たしていますが、名前を読むときに戸惑わないよう注意してください。
削除した詳細画面を参照しない
RouteDetailView.vue / RouteDetailMap.vue とルート名 route-detail は 09f2248 で削除されました。古い資料に残っていても使えません。
再作成中にほかのボタンは押せない
作成中は画面全体がロード画面に切り替わるため、決定・ホームに戻るは押せません。作成を途中で取り消す手段もありません。

✅ 動作確認方法

  1. npm run dev で起動し、ホームでジャンルと距離を選んで「ルートを作成」を押す
  2. 提案画面で「再作成」を押し、ロード画面が出て、終わると新しいルートに替わることを確かめる
  3. ローカルAPIを止める（または通信をオフラインにする）状態で「再作成」を押し、トーストでエラーが出て、直前のルートがそのまま見えることを確かめる
  4. 「決定」で案内画面へ直接進むこと、「ホームに戻る」でホームへ戻り、選んでいた条件が残っていることを確かめる
  5. 提案画面の URL（/suggestion）を直接開くか再読み込みすると、ホームへ戻されることを確かめる
  6. この機能専用の自動テストはありません。ルート作成の通信部分は frontend の npm test（src/services/__tests__/routeService.test.js）で確認できます
