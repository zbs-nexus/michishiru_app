🧩 先に知っておきたいこと

案内画面の地図は画面いっぱい
案内画面では地図を画面全体に敷き、その上に「次の目的地」バナー・前後のボタン・口コミの表示切り替え（上部）と終了ボタン（下部）を重ねています。 そのため、地図の本当の中心は、上下の操作に隠れていない「見えている範囲」の中心とずれます。
ズームレベル
地図の拡大率を表す数字で、1増えると縦横2倍に拡大されます。17 は横幅がおよそ190m（スマートフォンの画面で）で、最初の曲がり角まで見える程度です。
easeTo の offset
MapLibre GL の easeTo は地図を指定の中心へ動かす命令です。offset: [x, y] を付けると、その座標を地図の中心から x, y ピクセルずらした位置に置けます。
ResizeObserver
要素の大きさが変わったことを知らせてくれるブラウザの仕組みです。目的地の名前が長いとバナーが伸びるため、伸びたら位置を測り直すのに使います。

📖 この機能について

案内画面を開いた直後の地図の見え方と、地図の上のボタン配置を整えた変更です。

  • 案内開始時は、ルート全体を収めるのではなく、スタート地点を見えている範囲の中央に置き、固定の倍率（17）で表示する
  • 拡大・縮小のボタンを置かない（拡大率はピンチ操作で変える）
  • 口コミの表示切り替え（自分・みんな）を右寄せの縦並びにし、その下に現在地へ戻るボタンを置く

ルート提案画面の地図は従来どおり、ルート全体を収めて表示します。

🎯 なぜこの機能が必要？

案内を始めた瞬間に知りたいのは「どちらへ歩き出せばいいか」です。ルート全体を収めると縮小されすぎて最初の道が分からず、 さらに地図の中心が上下の操作の下に隠れて、スタート地点が見えにくくなっていました（US-6 案内画面表示）。

倍率を「1つ目の目的地までの区間が収まる値」にする案も一度実装されましたが（b204971）、目的地が遠いほど縮小されて同じ問題が起きるため、 24fc296 で固定の倍率に改めました。遠い目的地はバナーの距離とピンチでの縮小で確かめます。

🔄 処理の流れ

Step 1: 隠れている高さを測る（RouteNavigationView.vue）
onMounted で measureMapLayout() を呼び、上部の操作全体（.navigation-top）の下端を mapTopInsetPx、 画面の下端から終了ボタンの上端までを mapBottomInsetPx、口コミの表示切り替えの札の下端＋余白を mapControlsTopPx として求めます。 バナーの大きさが変わったら ResizeObserver で測り直します。
Step 2: 地図へ渡す（RouteNavigationMap.vue → RouteMap.vue）
案内画面の地図は should-center-on-origin を真にし、top-inset-px / bottom-inset-px / controls-top-px を渡します。
Step 3: スタート地点を中央に置く（RouteMap.vue の centerOnOrigin）
地図の読み込みが終わったら fitToInitialView() が呼ばれ、shouldCenterOnOrigin が真なら centerOnOrigin() で 経路の先頭（スタート地点）を、倍率17・見えている範囲の中央へアニメーションなしで置きます。経路が無ければ従来の fitToRoute() に切り替えます。
Step 4: コントロールの位置
地図右上のコントロール（現在地へ戻るボタン）は、CSS 変数 --map-controls-top で口コミの表示切り替えの札の下へ下げます。

💻 コードの解説

frontend/src/components/feature/route/RouteMap.vue

const toVisibleCenterOffsetY = () => (props.topInsetPx - props.bottomInsetPx) / 2;

const centerOnOrigin = () => {
  const originPosition = toOriginPosition(props.geometry);

  if (originPosition === null) {
    fitToRoute();
    return;
  }

  map.easeTo({
    center: originPosition,
    zoom: NAVIGATION_ZOOM_LEVEL,
    offset: [0, toVisibleCenterOffsetY()],
    duration: 0
  });
};
  • toVisibleCenterOffsetY: 上が隠れているぶん下へ、下が隠れているぶん上へずらす量（上下の差の半分）。現在地へ戻るボタンとチュートリアルの紫ピンへの移動でも同じ値を使います
  • duration: 0: 寄せ終わった状態を初期表示にするため、動かしません
  • props shouldCenterOnOrigin は既定が false で、案内画面だけが真にします

frontend/src/views/RouteNavigationView.vue（測る処理）

const measureMapInsets = () => {
  // 地図は画面全体に広がり上端が画面上端に一致するため、ビューポート基準で測れる
  const topBottomPx = navigationTopRef.value?.getBoundingClientRect().bottom;

  if (Number.isFinite(topBottomPx)) {
    mapTopInsetPx.value = Math.ceil(topBottomPx);
  }
  ...
    mapBottomInsetPx.value = Math.max(0, Math.ceil(window.innerHeight - endButtonTopPx));
};

地図が画面の上端から始まっているので、画面基準の座標（getBoundingClientRect）をそのまま地図の中のピクセルとして使えます。 地図の構成を変えて上端がずれた場合は、この前提が崩れる点に注意してください。

⚠️ 注意ポイント

拡大・縮小のボタンはもう無い
f6f7d46 で NavigationControl を外しました。拡大率はピンチ（PCではマウスホイール）で変えます。 古い解説書（次の目的地表示 の PR #59、現在地へ戻るボタン）にある「ズームボタン」の記述は当時のものです。
上部の操作を増やしたら測り直しの対象か確認する
mapTopInsetPx は .navigation-top の下端で測ります。上部に要素を足すときは .navigation-top の中に入れないと、スタート地点がその要素に隠れます。 ResizeObserver が見張っているのはバナーだけなので、ほかの要素の高さが後から変わる場合も測り直しが必要です。
初期表示は地図の読み込み完了時の値で決まる
onMounted で測った値が地図の読み込み時に使われます。測る前の値（0）で寄せると中央からずれるため、順序を変えないでください。

✅ 動作確認方法

  1. npm run dev で起動し、ルートを作って案内を開始する
  2. 開いた直後、スタート地点の「S」がバナーと終了ボタンに挟まれた範囲の中央にあり、周囲200m程度が見える倍率であることを確かめる
  3. 1つ目の目的地が遠いルートでも倍率が変わらないことを確かめる
  4. 地図の右上に拡大・縮小ボタンが無く、口コミの表示切り替え（縦並び）の下に現在地へ戻るボタンがあることを確かめる。名前の長い目的地でバナーが伸びても重ならないことも確かめる
  5. ルート提案画面では従来どおりルート全体が収まることを確かめる
  6. テスト: frontend で npm test（RouteMap.test.js の「固定の倍率（17）でスタート地点を…」「倍率は区間の長さで変えない」「拡大・縮小のボタンは置かず…」、RouteNavigationMap.test.js、RouteNavigationView.test.js）
