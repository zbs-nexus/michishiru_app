🧩 先に知っておきたいこと

spot と waypoint
spot（スポット）はユーザーが立ち寄る場所で1ルートに数個、waypoint（経由点）は経路の線を描くための座標の点で1ルートに数十個です。 バナーに出すのも「巡ったスポット数」に数えるのも spot です。混ぜると道の曲がり角まで数えてしまいます。
Composable
画面から切り出した「状態と処理のまとまり」です（use〇〇.js）。次の目的地の管理は useRouteProgress.js にまとまっています。
GPSの精度（accuracy）
「本当の位置はこの半径 ○m の円のどこか」という目安です。数字が小さいほど正確です。止まっていても数m揺れます。
geometry
経路の線の形（GeoJSON の LineString）です。coordinates に [経度, 緯度] の点（= waypoint）が並びます。

📖 この機能について

案内画面の上部に「次の目的地」のバナーを出し、目的地の名前と、そこまでの残り距離（経路沿い）を表示します。 スポットに着いたら利用者が「次の目的地へ」ボタンを押して次へ切り替えます。押したスポットは到達済みになり、地図の番号の丸が足跡の画像に変わります。 誤って押したときは「前の目的地へ」で1つずつ戻せます。すべて巡ると「すべての目的地を通過しました。開始地点へ戻ります」と表示します。

経緯: 2026-09-30 の初期実装では、現在地が次の目的地から40m以内に入ると自動で到達とし、次へ切り替えていました。 GPSの誤差で「立ち寄っていないのに到達」「立ち寄ったのに到達にならない」が起きるため、10/14（210eaca）でボタン操作のみに変わりました。

🎯 なぜこの機能が必要？

  • 地図だけでは「次にどこへ向かえばいいか」「あとどれくらいか」が分かりにくいため（US-6 案内画面表示）。
  • 直線距離だと、道が回り込んでいるときに実際より短く見えてしまうため（PR #57 で経路沿いの距離に変更）。
  • GPS は止まっていても数m揺れます。そのまま表示すると、歩いていないのに数字が動き続けて落ち着かないため。
  • 到達をGPSで自動判定すると誤判定が避けられないため、利用者自身が「着いた」と決められるようにしたため（PR #81）。

🔄 処理の流れ

useLocationTracking（現在地を受け取る）
   │  精度の悪い測位・徒歩ではあり得ない飛びは捨てる
   ▼
currentLocation
   │
   ▼
useRouteProgress（進み具合を管理）
   ├─「次の目的地へ」 → advanceToNextSpot()  → visitedSpotIds の末尾に追加
   ├─「前の目的地へ」 → returnToPreviousSpot() → visitedSpotIds の末尾を取り除く
   └─ 表示用の距離 = 経路に沿った距離（だめなら直線距離）
   │
   ├─▶ RouteNextSpotBanner（10m 単位に丸めて表示）
   ├─▶ RouteMap（到達済みのスポットは足跡の画像。区間の描き分けも更新）
   └─▶ walkStore.setVisitedSpotIds（結果画面の「巡ったスポット」）
Step 1: 現在地を受け取る（useLocationTracking.js）
ブラウザの watchPosition（位置が変わるたびに知らせてくれる機能）から現在地を受け取ります。精度が 100m より悪い測位は使わず前回の位置を保ちます。 2026-10-14 以降は、徒歩ではあり得ない速さの移動（座標の飛び）も捨てます（現在地のずれ対策）。
Step 2: ボタンで次の目的地を切り替える（useRouteProgress.js）
「次の目的地へ」で advanceToNextSpot() が今の目的地を到達済みにします。「前の目的地へ」で returnToPreviousSpot() が直前の1件を未到達へ戻します。 現在地から自動で切り替えることはありません。
Step 3: 残り距離を測る（useRouteProgress.js + routeGeometry.js）
現在地と次のスポットを、経路の線の上に「一番近い点」として落とし込み、その2点の間を線に沿って測ります。経路から 100m 以上離れているときは直線距離に切り替えます。
Step 4: 表示する（RouteNextSpotBanner.vue）
1km 未満は 10m 単位、1km 以上は 0.1km 単位で「約○m」「約○km」と表示します。目的地の名前は長くても省略せず、折り返して全文を出します。

💻 コードの解説

frontend/src/composables/useRouteProgress.js — 次の目的地の切り替え

const advanceToNextSpot = () => {
  if (nextSpot.value === null) {
    return;
  }

  visitedSpotIds.value = [...visitedSpotIds.value, nextSpot.value.spotId];
};

/** 前の目的地へ戻せるかどうか。到達済みが1件以上あるとき真 */
const canReturnToPreviousSpot = computed(() => visitedSpotIds.value.length > 0);

const returnToPreviousSpot = () => {
  if (!canReturnToPreviousSpot.value) {
    return;
  }

  visitedSpotIds.value = visitedSpotIds.value.slice(0, -1);
};
  • 入力: スポット一覧・現在地・経路の形。出力: nextSpot / distanceToNextM / visitedSpotIds / visitedCount / isCompleted / canReturnToPreviousSpot / advanceToNextSpot / returnToPreviousSpot。
  • nextSpot は「まだ visitedSpotIds に入っていない最初のスポット」です。
  • 配列は書き換えず、毎回新しい配列に丸ごと差し替えます。呼び出し側の watch が深い監視（deep）なしで変化を拾えるようにするためです。
  • 戻せるのは末尾の1件ずつだけです。すべて巡った後も戻せます。
  • ルート（spots）が差し替わったときだけ、到達状況をリセットします。

RouteNavigationView.vue — ボタンの配置

  • 画面上部の操作は .navigation-top の中に「バナー → 前後のボタンの段（.spot-step-row）→ 口コミの表示切り替え」の順に縦に積みます（PR #115）。目的地の名前が長くてバナーが伸びても、下の段が押し下げられるだけで重なりません。
  • 「前の目的地へ」は到達済みが無い（1スポット目）ときは出しません。「次の目的地へ」はすべて巡った後は出しません。片方だけでも段の高さは保ち、下の口コミの切り替えが跳ねないようにしています。
  • 「前の目的地へ」は主操作の「次の目的地へ」と区別するため、羊皮紙の面に紫の文字にしています（PR #108）。
  • 到達済みの数が変わると walkStore.setVisitedSpotIds() へ写します（結果画面の「巡ったスポット」）。

RouteMap.vue — 到達済みの足跡

到達済みのスポットは番号の丸に is-visited を付け、番号の文字を消して足跡の画像（assets/images/spot-visited-stamp.png）を背景に出します（PR #84）。 画像は表示サイズの3倍（96px）で用意し、高解像度の画面でもにじまないようにしています。口コミの場所の丸（紫・オレンジ）も到達済みになると同じ足跡に変わります。

frontend/src/utils/routeGeometry.js — 経路沿いの距離

関数やること
toRouteMeasure(coordinates)経路の各点までの累積距離（スタートから何m目か）を先に計算しておく。これが routeMeasure。ルートが変わったときだけ作り直すので、現在地が動くたびの計算が軽くなる
toRouteProjection(measure, position)座標を経路の線上の一番近い点に落とし込み、「スタートから何m目か（alongM）」と「線からどれだけ離れているか（deviationM）」を返す
calculateAlongRouteDistanceM(...)現在地と目的地の alongM の差 = 経路に沿った距離（alongRouteDistanceM）。現在地が maxDeviationM より離れていたら null

線からの距離が大きいときに使わない理由: 経路から遠く離れると、「一番近い点」が全然違う区間（たとえば帰り道の部分）に吸い寄せられ、距離が急に何百mも飛ぶことがあるためです。

計算では、狭い範囲なら地球を平面とみなしてよいので、緯度・経度をメートルに換算してから点と線分の距離を求めています。2点間の直線距離は utils/geoDistance.js の calculateDistanceM（ハバーサイン公式という、球面上の距離を求める式）を使います。

frontend/src/composables/useLocationTracking.js — GPSの揺らぎ対策

次の3つのどれかに当てはまれば、その測位を現在地として採用します（①精度の判定）。

  1. 最初の1回目（これを捨てると、精度が悪い場所では案内が始まらない）
  2. 精度が 100m 以内
  3. 最後に採用してから 10 秒以上たった（PR #62 で追加。ビル街などで精度の悪い測位しか来ないと、現在地がずっと動かなくなるため）

PR #62 では上限を 50m → 100m に緩めました。開発者ツールで位置を偽装したときも精度が大きめに返るためです。

2026-10-14（4d4cbb4）からは、①を通った測位にも②速さの判定がかかります。詳しくは 現在地のずれ対策 を参照してください。

RouteNextSpotBanner.vue — 表示

  • 表示だけを担当し、到達の管理はしません（値は親の RouteNavigationView.vue から受け取ります）。
  • 丸めた結果が 0m になると「着いたのに0m」と読めるので、最小でも「約10m」と出します。
  • 目的地の名前は省略記号（…）で切らず、overflow-wrap: anywhere で折り返して全文を出します（PR #115）。区切りの無い長い英数字の店名も枠からはみ出しません。
  • 左にマスコットを添え、経験値バーは experience スロットから差し込みます（マスコットのレベルアップ）。
  • role="status" / aria-live="polite" を付け、スクリーンリーダーにも内容の変化を伝えます。そのためバーやマスコットは装飾扱い（is-decorative）にしています。

RouteNavigationView.vue — 追跡を1か所にまとめる

現在地の追跡はこの画面で1回だけ開始し、地図とバナーの両方に同じ値を渡します。地図とバナーがそれぞれ追跡すると、watchPosition が二重に動いてしまうためです。

PR #59 — 地図上の要素の重なり修正

  • 経緯: 案内画面では、地図のズームボタンがバナーの下に隠れて押せなかったため、RouteNavigationMap.vue でボタンを 84px 下げました。PR #115 で固定値をやめ、上部の操作の高さを測って追従させる形（mapControlsTopPx）に変わり、さらに 2026-10-28（f6f7d46）で案内画面の拡大・縮小ボタン自体が削除されました（案内開始時の地図表示）。
  • 位置情報のエラー表示が終了ボタンと重なっていたため、上へずらしました。
  • RouteMap.vue のお知らせ表示が、地図の帰属表示（右下の i マーク）を覆っていたので右端を空けました。帰属表示は地図の利用規約上、隠してはいけません。

⚠️ 注意ポイント

次の目的地を切り替える手段はボタンだけ
現在地から自動で到達にする処理はありません。到達の自動判定を戻したくなった場合は、PR #81 で廃止した理由（GPSの誤判定）を踏まえて検討してください。
到達済みは「順番どおり」
切り替えられるのは nextSpot（次の1件）だけで、戻せるのも末尾の1件だけです。順番を飛ばして先のスポットを到達済みにすることはできません。
チュートリアル中の制限
チュートリアル中は「次の目的地へ」を決まった段階でしか押せず、「前の目的地へ」で段階も1つ戻ります（チュートリアル）。ボタンに手を入れるときはこの分岐も確認してください。
定数を足すときは用語辞書へ
新しい定数を足すときは、先に naming-glossary.md へ登録してください。

✅ 動作確認方法

  1. リポジトリのルートで npm run dev を実行します。
  2. ホーム画面からルートを作成し、「決定」で案内画面へ進みます。
  3. 上部に「次の目的地」と名前・距離が出ることを確認します。名前の長いスポットでも省略されず、下のボタンと重ならないことを確認します。
  4. Chrome の開発者ツール（F12 →「︙」→「More tools」→「Sensors」→「Location」）で位置を動かし、距離が変わることを確認します。スポットに近づけても自動では切り替わらないことも確認します。
  5. 「次の目的地へ」を押すと次のスポットに切り替わり、地図の丸が足跡になることを確認します。「前の目的地へ」で1つ戻り、足跡も消えることを確認します。1スポット目では「前の目的地へ」が出ないことも確認します。
  6. 全スポットを巡ると「すべての目的地を通過しました」と出て、「次の目的地へ」が消えることを確認します。
  7. 自動テスト: frontend/ で npm test。src/composables/__tests__/useRouteProgress.test.js（進める・戻す）、src/components/feature/route/__tests__/RouteNextSpotBanner.test.js（全文表示）、src/views/__tests__/RouteNavigationView.test.js（ボタンの出し分け）があります。
  8. frontend/ で npm run lint と npm run build を実行します。
