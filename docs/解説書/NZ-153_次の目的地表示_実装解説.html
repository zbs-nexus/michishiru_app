📖 この機能について

案内画面の上部に「次の目的地」のバナーを出し、目的地の名前と、そこまでの残り距離を表示します。目的地の近く（40m以内）まで来ると「到達した」と判定し、自動で次の目的地に切り替わります。すべて回ると「すべての目的地を通過しました。開始地点へ戻ります」と表示します。

先に知っておきたい用語

用語意味
spot（スポット）ユーザーが立ち寄る場所（公園・神社・カフェ等）。1ルートに数個。バナーに出すのはこちら
waypoint（経由点）経路の線を描くための座標の点（交差点・道の折れ点）。1ルートに数十個。ユーザーには見せない
geometry経路の線の形。coordinates に [経度, 緯度] の点（= waypoint）が並ぶ
GPSの精度（accuracy）「本当の位置はこの半径 ○m の円のどこか」という目安。数字が小さいほど正確

spot と waypoint を混ぜると「巡ったスポット数」に道の曲がり角まで数えてしまうので、必ず区別します。

🎯 なぜこの機能が必要？

  • 地図だけでは「次にどこへ向かえばいいか」「あとどれくらいか」が分かりにくいため。
  • 直線距離だと、道が回り込んでいるときに実際より短く見えてしまうため（PR #57 で経路沿いの距離に変更）。
  • GPS は止まっていても数m揺れます。そのまま表示すると、歩いていないのに数字が動き続けて落ち着かないため。

🔄 処理の流れ

useLocationTracking（現在地を受け取る）
   │  精度の悪い測位は捨てる（ただし10秒以上止まったら受け入れる）
   ▼
currentLocation / accuracy
   │
   ▼
useRouteProgress（進み具合を計算）
   ├─ 直線距離 ≦ 40m なら到達 → visitedSpotIds に追加 → 次のスポットへ
   └─ 表示用の距離 = 経路に沿った距離（だめなら直線距離）
   │
   ▼
RouteNextSpotBanner（10m 単位に丸めて表示）
Step 1: 現在地を受け取る（useLocationTracking.js）
ブラウザの watchPosition（位置が変わるたびに知らせてくれる機能）から現在地を受け取ります。精度が 100m より悪い測位は「座標が大きく飛ぶ」ので使わず、前回の位置を保ちます。
Step 2: 到達したか判定する（useRouteProgress.js）
現在地が更新されるたびに、次のスポットまでの直線距離を測ります。40m 以内なら到達済みにして、次のスポットへ進めます。
Step 3: 残り距離を測る（useRouteProgress.js + routeGeometry.js）
現在地と次のスポットを、経路の線の上に「一番近い点」として落とし込み、その2点の間を線に沿って測ります。経路から 100m 以上離れているときは直線距離に切り替えます。
Step 4: 表示する（RouteNextSpotBanner.vue）
1km 未満は 10m 単位、1km 以上は 0.1km 単位で「約○m」「約○km」と表示します。

💻 コードの解説

frontend/src/composables/useRouteProgress.js — 到達判定

watch([currentLocation, accuracy], () => {
  // 初回の測位までは現在地に仮の座標が入っているため、判定しない
  if (accuracy.value === null || nextSpot.value === null) {
    return;
  }

  const distanceM = straightDistanceToNextM.value;

  if (distanceM === null || distanceM > ARRIVAL_THRESHOLD_M) {
    return;
  }

  visitedSpotIds.value = [...visitedSpotIds.value, nextSpot.value.spotId];
});
  • 入力: スポット一覧・現在地・精度・経路の形。出力: nextSpot / distanceToNextM / visitedSpotIds / visitedCount / isCompleted。
  • nextSpot は「まだ visitedSpotIds に入っていない最初のスポット」です。
  • 到達済みは追加するだけで、取り消しません。GPS が前後にぶれても案内が逆戻りしないためです。
  • ルート（spots）が差し替わったときだけ、到達状況をリセットします。

判定は直線、表示は経路沿い。なぜ分けるのか

到達判定まで経路沿いの距離にすると、ユーザーが近道して経路から外れた場所でスポットに着いたとき、「経路上ではまだ遠い」と判断されて到達になりません。そこで、判定は直線距離（いま実際にどれだけ近いか）、表示は経路沿い（あとどれだけ歩くか）と使い分けています。

frontend/src/utils/routeGeometry.js — 経路沿いの距離

関数やること
toRouteMeasure(coordinates)経路の各点までの累積距離（スタートから何m目か）を先に計算しておく。これが routeMeasure。ルートが変わったときだけ作り直すので、現在地が動くたびの計算が軽くなる
toRouteProjection(measure, position)座標を経路の線上の一番近い点に落とし込み、「スタートから何m目か（alongM）」と「線からどれだけ離れているか（deviationM）」を返す
calculateAlongRouteDistanceM(...)現在地と目的地の alongM の差 = 経路に沿った距離（alongRouteDistanceM）。現在地が maxDeviationM より離れていたら null

線からの距離が大きいときに使わない理由: 経路から遠く離れると、「一番近い点」が全然違う区間（たとえば帰り道の部分）に吸い寄せられ、距離が急に何百mも飛ぶことがあるためです。

計算では、狭い範囲なら地球を平面とみなしてよいので、緯度・経度をメートルに換算してから点と線分の距離を求めています。2点間の直線距離は utils/geoDistance.js の calculateDistanceM（ハバーサイン公式という、球面上の距離を求める式）を使います。

frontend/src/composables/useLocationTracking.js — GPSの揺らぎ対策

// 測位そのものは届いているため、精度に関わらずエラー表示を解除する
trackingError.value = null;

const isFirstFix = accuracy.value === null;
const isReliableAccuracy =
  Number.isFinite(positionAccuracy) &&
  positionAccuracy <= MAX_ACCEPTABLE_ACCURACY_M;
// 精度が悪い測位しか来ない環境で、現在地が固まったままにならないようにする
const isPositionStale =
  lastAcceptedAt !== null && Date.now() - lastAcceptedAt >= MAX_POSITION_AGE_MS;

if (!isFirstFix && !isReliableAccuracy && !isPositionStale) {
  return;
}

次の3つのどれかに当てはまれば、その測位を現在地として採用します。

  1. 最初の1回目（これを捨てると、精度が悪い場所では案内が始まらない）
  2. 精度が 100m 以内
  3. 最後に採用してから 10 秒以上たった（PR #62 で追加。ビル街などで精度の悪い測位しか来ないと、現在地がずっと動かなくなるため）

PR #62 では上限を 50m → 100m に緩めました。開発者ツールで位置を偽装したときも精度が大きめに返るためです。

定数の一覧

定数値場所意味
ARRIVAL_THRESHOLD_M40useRouteProgress.jsこの距離以内に入ったら到達
MAX_ROUTE_DEVIATION_M100useRouteProgress.js経路からこれ以上離れたら直線距離に切り替え
MAX_ACCEPTABLE_ACCURACY_M100useLocationTracking.jsこれより精度が悪い測位は採用しない
MAX_POSITION_AGE_MS10000useLocationTracking.js採用が途切れてこの時間がたったら、精度が悪くても受け入れる
DISTANCE_ROUNDING_UNIT_M10RouteNextSpotBanner.vue距離表示を丸める単位

RouteNextSpotBanner.vue — 表示

  • 表示だけを担当し、到達判定はしません（値は親の RouteNavigationView.vue から受け取ります）。
  • 丸めた結果が 0m になると「着いたのに0m」と読めるので、最小でも「約10m」と出します。
  • role="status" / aria-live="polite" を付け、スクリーンリーダーにも内容の変化を伝えます。

RouteNavigationView.vue — 追跡を1か所にまとめる

現在地の追跡はこの画面で1回だけ開始し、地図とバナーの両方に同じ値を渡します。地図とバナーがそれぞれ追跡すると、watchPosition が二重に動いてしまうためです。

PR #59 — 地図上の要素の重なり修正

  • 案内画面では、地図のズームボタンがバナーの下に隠れて押せなかったため、RouteNavigationMap.vue でボタンを 84px 下げました。
  • 位置情報のエラー表示が終了ボタンと重なっていたため、上へずらしました。
  • RouteMap.vue のお知らせ表示が、地図の帰属表示（右下の i マーク）を覆っていたので右端を空けました。帰属表示は地図の利用規約上、隠してはいけません。

⚠️ 注意ポイント

到達判定は「順番どおり」
判定するのは nextSpot（次の1件）だけです。順番を飛ばして先のスポットに行っても、そのスポットは到達になりません。
初回の測位までは判定しない
測位前の現在地には仮の座標（フォールバック値）が入っています。accuracy が null の間は判定しないことで、仮の座標が偶然スポットに近くても誤って到達にしないようにしています。
定数を変えるときはセットで考える
ARRIVAL_THRESHOLD_M を GPS の誤差（数十m）より小さくすると、到達できなくなることがあります。新しい定数を足すときは、先に naming-glossary.md へ登録してください。

✅ 動作確認方法

  1. リポジトリのルートで npm run dev を実行します。
  2. ホーム画面からルートを作成し、「決定」で案内画面へ進みます。
  3. 上部に「次の目的地」と名前・距離が出ることを確認します。
  4. 位置を動かして確認します。Chrome の場合:
    • F12 で開発者ツールを開き、右上の「︙」→「More tools」→「Sensors」を開く
    • 「Location」で「Other…」を選び、緯度・経度を入力する
    • スポットの座標に近い値を入れると、到達して次の目的地に切り替わる
  5. 全スポットに到達すると「すべての目的地を通過しました」と出ることを確認します。
  6. ズームボタンがバナーに隠れず押せること、エラー表示が終了ボタンと重ならないことを確認します。
  7. frontend/ で npm run lint と npm run build を実行します。フロントの自動テストツールは未導入のため、計算部分（routeGeometry.js など）のテストはまだありません。
