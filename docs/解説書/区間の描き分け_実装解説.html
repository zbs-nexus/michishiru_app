区間の描き分け - 実装解説

🗓 対象期間: 2026-10-21
📅 マージ日: 2026-10-21（12:11）
🌿 対象ブランチ: feature/NZ-173
🔖 対象マージ: 40e902e（次目的地の経路の色変更）

🧩 先に知っておきたいこと

区間（leg）
ルートを開始地点とスポットで区切った1区間です。スポットが3か所なら「開始→1」「1→2」「2→3」「3→開始（帰り道）」の4区間、つまりスポット数+1本になります。 Amazon Location Service（Routes）の応答の Legs がそのまま区間に対応します。
次の目的地と到達済みの数
案内画面では「次の目的地へ」ボタンで到達済みのスポットが1つずつ増えます（次の目的地表示）。 到達済みの数（visitedCount）がそのまま「今の区間の番号」になります。
MapLibre GL のソースとレイヤー
地図ライブラリ MapLibre GL では、描きたいデータ（GeoJSON）を「ソース」に入れ、その見た目（色・太さ・破線）を「レイヤー」で決めます。 後から足したレイヤーほど手前に描かれます。

📖 この機能について

案内画面の経路の線を、区間ごとに3通りに描き分ける機能です。

区間見た目コード上の名前
歩き終えた区間灰色の破線（細め）walkedLegs
今の区間（次の目的地まで）緑の太線＋白の縁取り。最前面currentLeg
これからの区間従来の経路の色（青）upcomingLegs

全スポットを巡り終えると、帰り道（最後の区間）が今の区間として緑になります。

🎯 なぜこの機能が必要？

周回コースでは行きと帰りの道が重なったり交差したりするため、1色の線だと「今どの線をたどればいいか」が分かりにくい問題がありました。 次の目的地までの道だけを目立たせ、歩き終えた道を薄くすることで、案内中の迷いを減らします（US-6 案内画面表示の改善）。

🔄 処理の流れ

Step 1: 区間ごとの線を受け取る（routesRepository.js）
CalculateRoutes に LegGeometryFormat: 'Simple' を指定して区間ごとの座標列を得て、 extractLegCoordinates が区間ごとに間引いた座標列（legCoordinates）を返します。
Step 2: 区間の数を確かめて応答に載せる（service.js の toRouteLegs）
区間の数がスポット数+1で、すべて2点以上なら legs として返します。合わなければ空配列にします（スポットとの対応を保証できないため）。 スポットの除外・差し込みを終えた最終のスポットと経路で確かめます。
Step 3: 画面用の形に変換（routeResponse.js の toLegs）
各区間を { geometry: { type: 'LineString', coordinates } } にします。1つでも線にならない区間があれば全体を空にします。
Step 4: 3つに分ける（routeLegs.js の toRouteLegSections）
案内画面の computed（legSections）が、区間の一覧・スポット数・到達済みの数から「歩き終えた・今・これから」に分けます。 前提を確かめられなければ null を返します。
Step 5: 描く（RouteMap.vue）
legSections が null なら従来どおり全体を1色で描きます。あれば、青の線にはこれからの区間だけを入れ、 歩き終えた区間（破線）と今の区間（縁取り＋緑）を別のソース・レイヤーで重ねます。「次の目的地へ」を押すたびに legSections が変わり、データだけを差し替えます。

💻 コードの解説

frontend/src/utils/routeLegs.js

export const toRouteLegSections = ({ legs, spotCount, visitedCount }) => {
  ...
  if (!Number.isInteger(spotCount) || spotCount < 1 || legs.length !== spotCount + 1) {
    return null;
  }
  ...
  const currentLegIndex = visitedCount;
  const geometries = legs.map((leg) => leg.geometry);

  return {
    walkedLegs: geometries.slice(0, currentLegIndex),
    currentLeg: geometries[currentLegIndex],
    upcomingLegs: geometries.slice(currentLegIndex + 1)
  };
};
  • 入力: 区間の一覧・スポット数・到達済みの数
  • 出力: { walkedLegs, currentLeg, upcomingLegs }、または確かめられないとき null
  • Vue に依存しない純関数なので、src/utils/__tests__/routeLegs.test.js で単体テストしています

frontend/src/components/feature/route/RouteMap.vue（描画）

const sections = props.legSections;
const routeData =
  sections === null ? routeFeature : toLegFeatureCollection(sections.upcomingLegs);
const walkedData = toLegFeatureCollection(sections === null ? [] : sections.walkedLegs);
const currentData = toLegFeatureCollection(sections === null ? [] : [sections.currentLeg]);
  • 描き分けるときは、青の線に全体ではなく「これからの区間」だけを入れます。全体を青で描くと、破線の隙間から青が透けて見えるためです
  • 歩き終えた区間の端は butt（四角）にしています。丸めると短い破線が点に潰れるためです
  • 今の区間のレイヤーは最後に足し、ほかの区間と交差しても最前面に出します
  • 進めるたびに地図を寄せ直す（fit）ことはしません。利用者が動かした地図の位置が戻ってしまうためです

⚠️ 注意ポイント

色は2か所で持っている
MapLibre GL の線の色は CSS 変数を読めないため、mapDefaults.js の定数と global.css の --route-walked-leg / --route-current-leg に同じ色を書いています。変えるときは両方直してください。
区間が無い応答でも壊れない
古い応答（getRoute の保存済みルートなど）や区間の数が合わない場合は legs が空になり、全体を1色で描きます。 区間を前提にした処理を足すときは、この「区間なし」の道を必ず残してください。
案内画面だけが描き分ける
legSections を渡すのは案内画面（RouteNavigationMap）だけです。ルート提案画面の地図は従来どおり1色です。

✅ 動作確認方法

  1. npm run dev で起動し、ルートを作って案内を開始する
  2. 開始地点から1つ目のスポットまでが緑の太線、それ以外が青で描かれることを確かめる
  3. 「次の目的地へ」を押すたびに、歩き終えた区間が灰色の破線になり、緑の区間が次へ移ることを確かめる。「前の目的地へ」で戻ることも確かめる
  4. 全スポットを巡ると、帰り道が緑になることを確かめる
  5. テスト: frontend で npm test（routeLegs.test.js / routeResponse.test.js / RouteMap.test.js / RouteNavigationView.test.js）、 backend で npm test（createRoute/__tests__/routesRepository.test.js / service.test.js）
