🌿 対象ブランチ: feature/NZ-274
🔖 対象マージ: 4d4cbb4（GPS取得処理の修正: 速度で「ありえない移動」を捨てる）

🧩 先に知っておきたいこと

現在地の追跡（watchPosition）
案内画面はブラウザの watchPosition で現在地を受け取り続けます。仕組みは 現在地取得機能の実装解説、 精度による測位の取捨（100m・10秒ルール）は 次の目的地表示 の「GPSの揺らぎ対策」を先に読んでください。
マルチパス
高いビルが並ぶ場所で、GPSの電波が壁に反射してから届く現象です。端末が申告する精度（accuracy）は良いままなのに、座標だけが数十〜数百m飛ぶことがあります。 そのため「精度が悪い測位を捨てる」だけでは防げません。
表示用の座標と計算用の座標
この機能では「地図に出す現在地（displayLocation）」と「距離の計算に使う現在地（currentLocation）」を分けます。混ぜると歩いた距離が狂います。

📖 この機能について

ビル街で現在地のマーカーが建物の中や隣の通りへ飛ぶ問題への対策で、2つの仕組みからなります。

仕組みやること効く場所
② 速さの判定前回採用した地点から、徒歩ではあり得ない速さ（秒速3m超）で動いた測位を「座標の飛び」として捨てる現在地そのもの（距離の計算にも効く）
経路への吸着経路の線から40m以内にいる間は、地図の現在地マーカーを線上の最も近い点に寄せて表示する地図の表示だけ

🎯 なぜこの機能が必要？

現在地が飛ぶと、案内中に「自分がどこにいるか」を見失います。さらに、飛んだ座標まで歩いたことにすると、散歩の実績の距離が実際より長くなります。 関連するユーザーストーリーは US-6（案内画面表示）と US-8（散歩結果の総距離）です。

🔄 処理の流れ

watchPosition の測位
   │
   ▼  useLocationTracking
① 精度の判定（100m以内 / 初回 / 10秒以上採用が途切れた）
   │  通らなければ捨てる
   ▼
② 速さの判定（isPlausibleWalkingMove）
   │  徒歩であり得ない → 飛びの候補として数える（3回続けて矛盾しなければ受け入れる）
   ▼
currentLocation ──┬─▶ useRouteProgress（次の目的地までの距離）
                  ├─▶ useWalkRecord（歩いた距離）
                  └─▶ useRouteSnapping ─▶ displayLocation ─▶ 地図の現在地マーカー
Step 1: 精度の判定（従来どおり）
初回の測位はそのまま採用します。2回目以降は精度が100m以内、または最後の採用から10秒以上たったものだけを次へ進めます。
Step 2: 速さの判定（新規）
前回採用した測位から今回の測位までの距離を、経過時間で割って速さを求めます。秒速3mを超えれば飛びとして捨てます。 精度の救済（10秒ルール）で通った測位にもかけます。精度の悪い測位ほど飛びやすいためです。
Step 3: 飛びが続いたら受け入れる
前回の採用地点そのものが間違っていた場合（初回の測位が飛んでいた等）、正しい測位がずっと「飛び」と判定され、現在地が固まってしまいます。 そこで、飛びと判定した測位どうしが互いに矛盾しない（徒歩でつながる）まま3回続いたら、そちらを正しいとみなして受け入れます。
Step 4: 表示だけ経路へ吸着させる
RouteNavigationView が useRouteSnapping で吸着後の displayLocation を作り、地図（RouteNavigationMap の current-location）にだけ渡します。 距離の計算には吸着前の currentLocation を渡します。

💻 コードの解説

frontend/src/utils/locationPlausibility.js

export const MAX_WALKING_SPEED_MPS = 3;

export const isPlausibleWalkingMove = (from, to) => {
  const distanceM = calculateDistanceM(from, to);

  if (distanceM === null) {
    return true;
  }

  const marginM =
    (Number.isFinite(from.accuracy) ? from.accuracy : 0) +
    (Number.isFinite(to.accuracy) ? to.accuracy : 0);

  const elapsedS = Math.max((to.timestamp - from.timestamp) / 1000, MIN_ELAPSED_S);

  return distanceM - marginM <= MAX_WALKING_SPEED_MPS * elapsedS;
};
  • 入力: 前回と今回の測位（緯度・経度・精度・時刻）
  • 出力: 徒歩で起こり得る移動なら true
  • 距離から両方の精度の幅を差し引いてから速さを判定します。精度の円の中の揺れは、本当に動いたのか区別できないので捨てません
  • 経過時間が長いほど許す距離も伸びるので、本当に移動した場合は時間がたてば採用されます
  • 同じ時刻の測位で0で割らないよう、経過時間は最低1秒として扱います
  • 座標が不正で判定できないときは true（捨てない）にしています

⚠️ 注意ポイント

吸着後の座標を距離の計算に使わない
displayLocation を useWalkRecord や useRouteProgress に渡すと、経路から外れて近道した区間も経路沿いの長さで数えてしまいます。 地図のマーカー以外では必ず currentLocation を使ってください。
しきい値は互いに関係している
速さの上限（秒速3m）は早歩き・小走りを捨てない値です。小さくしすぎると、本当に歩いた測位まで捨てて現在地が遅れます。 ジョギングのような使い方を想定するなら見直しが必要です。
自動テストが無い
このマージで追加した locationPlausibility.js と useRouteSnapping.js には、現時点で専用のテストファイルがありません。 しきい値を変えるときは手動での確認が必要です。

✅ 動作確認方法

  1. npm run dev で起動し、ルートを作って案内を開始する
  2. Chrome の開発者ツール（F12 →「︙」→「More tools」→「Sensors」→「Location」）で、経路の近く（40m以内）の座標を入れ、現在地マーカーが線の上に表示されることを確かめる
  3. 経路から100m程度離れた座標を入れ、マーカーが線から外れた位置にそのまま出ることを確かめる
  4. 1秒ほどの間に数百m離れた座標へ切り替え、マーカーがすぐには飛ばないこと、同じ付近の座標を続けて入れると3回目で移ることを確かめる
  5. frontend で npm run lint と npm run build、npm test（既存の RouteNavigationView.test.js などが壊れていないこと）
